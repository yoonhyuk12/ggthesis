## 4.1 데이터셋 및 평가 지표

### 알고자 하는 것
4.2~4.4 분석에 쓸 **정답지(Ground Truth)**를 만든다. 즉 시스템이 알린/막은 사진이 실제로 진짜 위험이었는지 가짜경보였는지를 사람이 판정한 데이터.

### 사전조건
- 협력 현장 2~5개소에서 본 시스템을 2~4주간 운영하여 데이터 누적
- `D:\onvifcctv\alert_snapshots\` (LLM 통과), `blocked_snapshots\` (LLM 차단) 양쪽에 사진 누적
- 옵션 A 적용 후 누적된 데이터일 것 (yolo_confidence가 채워져 있어야 4.2 가능)

### 절차

- [ ] **1단계: 표본 추출**
  - 두 폴더에서 무작위 500~1,000장 추출
  - 정탐(alert)·오탐(blocked)·클래스별(안전모·낙상·제한구역 등) 균형 고려
  - 추출 결과는 `thesis_data.db`(옵션 B 산출물)의 `detections` 테이블로 import

- [ ] **2단계: 라벨링 기준표 작성**
  - "진짜 위험"의 정의 명문화 (예: "산업안전보건기준 위반에 해당하는 행위·상태")
  - 경계 사례 가이드 (예: "안전모를 벗어 손에 들고 있는 경우 → 진짜 위험")
  - 1페이지 분량, 라벨러에게 사전 배포

- [ ] **3단계: 사람 라벨링 (라벨러 2명)**
  - 각 이미지를 독립적으로 ⭕(진짜 위험) / ❌(가짜 경보) / ⏭️(판단 불가) 표시
  - 옵션 B의 `02_labeling_ui.py` GUI 사용
  - 라벨러 자격: 안전관리자, 안전 관련 학과 대학원생/교수, 또는 박종용 교수 지도하에 본인+1인

- [ ] **4단계: 신뢰도 검증 (Cohen's Kappa)**
  - 두 라벨러 결과의 일치도 계산
  - Kappa ≥ 0.7 권장 (substantial agreement)
  - 불일치 사례는 두 사람이 토론 후 합의

- [ ] **5단계: 평가 지표 정의 문서화**
  - Precision, Recall, F1, FAR(건/시간), mAP@0.5
  - 토큰 비용·지연시간 등 부수 지표

### 산출물
- `thesis_data.db` `gt_labels` 테이블 (라벨러·일치도 포함)
- 라벨링 기준표 PDF (논문 부록)

## 4.2 1차 YOLO 검출 성능 평가 (임계값 비교)

### 알고자 하는 것
**"임계값 0.3 전략이 0.5·0.4 대비 어떤 trade-off를 가지는가"** — 본 연구의 SDT 기반 역할분담(1차는 recall 극대화) 정당성 검증.

### 사전조건
- 옵션 A 완료 → `history.db`의 `yolo_confidence` 컬럼이 채워져 있음
- 4.1 GT 라벨링 완료

### 절차

- [ ] **1단계: SQL 분석**

  ```sql
  -- history.db에서 임계값별 검출 건수
  SELECT
      CASE
          WHEN yolo_confidence >= 0.5 THEN '0.5'
          WHEN yolo_confidence >= 0.4 THEN '0.4'
          WHEN yolo_confidence >= 0.3 THEN '0.3'
      END AS threshold,
      COUNT(*) AS detections
  FROM history
  GROUP BY threshold;
  ```

## 4.3 LLM 백업 검증의 오탐률 감소 효과 ⭐ 핵심 결과 1

### 알고자 하는 것
**"2차 LLM이 있으면 가짜경보가 얼마나 줄어드는가"** — 본 연구의 메인 가설 검증.

가설: 2단계 파이프라인(YOLO 0.3 + LLM)은 1차 단독(0.3)과 동등한 recall을 유지하면서 1차(0.5)보다 낮은 FAR을 달성한다.

### 사전조건
- 4.1 GT 라벨링 완료
- `history.db`의 `second_judgment` 컬럼이 PASS/BLOCK으로 채워져 있음

### 절차

- [ ] **1단계: 두 가상 시스템 정의**
  - **시스템 A (1차 단독):** `history.db`의 모든 row를 알림으로 간주 (yolo_confidence ≥ 0.3 전체)
  - **시스템 B (2단계):** `second_judgment = 'PASS'`인 row만 알림 (LLM 통과분)

- [ ] **2단계: FAR 계산**
  ```
  FAR (건/시간) = 오경보 건수(FP) / 총 운영 시간
  ```
  - 총 운영 시간은 `history.db`의 timestamp 범위로 산출

- [ ] **3단계: 핵심 비교표 작성**

  | 지표 | 1차 단독 (0.5) | 1차 단독 (0.3) | **2단계 (0.3+LLM)** |
  |---|---|---|---|
  | 총 경보 건수 | | | |
  | 진경보(TP) | | | |
  | 오경보(FP) | | | |
  | 미경보(FN) | | | |
  | FAR (건/시간) | | | |
  | Precision | | | |
  | Recall | | | |
  | F1 | | | |

- [ ] **4단계: 정성 분석 사례 선정**
  - **오탐 제거 성공:** 3건 (예: 나뭇가지→사다리 / 작업복 줄무늬→안전조끼 / 쪼그려 앉기→낙상)
  - **정탐 유지:** 1건 (예: 비계 위 안전대 미착용)
  - **오판 사례:** 1~2건 (LLM이 정탐을 잘못 기각한 케이스 — 4.6 한계 + Few-shot 교정 필요성으로 연결)
  - 각 사례마다 검출 이미지 + LLM 사유(`second_reason`)를 본문 또는 부록에 첨부

### 산출물
- 표 4-2: 1차 단독 vs 2단계 비교

## 4.4 Few-shot Learning의 효과 분석 ⭐ 핵심 결과 2

### 알고자 하는 것
세 가지 질문 동시 검증:
1. **Few-shot이 진짜 효과 있나?** (k=0 vs k=5) — 본 연구의 사용자 교정 시스템 정당화
2. **예시 몇 개가 적당한가?** (k=1·3·5) — 비용 대비 최적 k 도출
3. **규칙도 같이 알려주면 더 좋아지나?** (k=5 ± 도메인 컨텍스트) — 향후 연구 방향

### 사전조건
- 4.1 GT 라벨링 완료
- 협력 현장 카메라 중 일부에 **Few-shot 슬롯 5개를 미리 등록** (Pro 플랜)
  - 위양성 사례 3개 + 진양성 사례 2개 권장
- 옵션 B 분석 도구의 batch LLM 호출 스크립트 준비

### 핵심 아이디어 (영상 재실행 불필요)
카메라·영상을 다시 돌리지 않고, **이미 캡처된 이미지 파일을 LLM API에 batch로 다시 보냄**. 1회 batch 실행으로 5조건 동시 측정.

### 절차

- [ ] **1단계: 표본 선정**
  - `thesis_data.db`에서 GT 라벨이 있는 사진 중 100~200장 추출
  - Few-shot 슬롯이 등록된 카메라의 사진 우선

- [ ] **2단계: batch LLM 재호출 스크립트**

  ```python
  # 의사코드 (옵션 B의 05_analyze_fewshot.py)
  samples = few_shot_store.list_samples(camera)  # 등록된 5개

  for image in test_images:
      for k in [0, 1, 3, 5]:
          selected = samples[:k]
          # 조건 1~4
          result = call_llm(image, few_shot_examples=selected, domain_context=False)
          save_result(image_id, k, domain=False, result)

      # 조건 5: k=5 + 도메인 컨텍스트
      result = call_llm(image, few_shot_examples=samples, domain_context=True)
      save_result(image_id, k=5, domain=True, result)
  ```

- [ ] **3단계: 5조건 비교표 작성**

  | 조건 | Precision | Recall | F1 | 평균 토큰 | 추론 시간(ms) |
  |---|---|---|---|---|---|
  | k=0 (Zero-shot) | | | | | |
  | k=1 | | | | | |
  | k=3 | | | | | |
  | k=5 | | | | | |
  | k=5 + 도메인 컨텍스트 | | | | | |

- [ ] **4단계: 결과 해석**
  - k 한계 효용 (어디서 saturating)
  - 도메인 컨텍스트의 독립적 기여
  - 비용 대비 최적 조건 도출

### 산출물
- 표 4-3: Few-shot 5조건 비교
- 그림 4-8: k별 F1 곡선 + 도메인 컨텍스트 효과 막대그래프

### 예상 소요 시간
- batch 스크립트 작성: 0.5일
- batch 실행: 200장 × 5조건 = 1,000회 호출, **약 30분~1시간 (대기 포함)**
