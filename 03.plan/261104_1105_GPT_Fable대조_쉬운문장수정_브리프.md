# GPT·Fable 조사 대조 및 쉬운 문장 수정

## 승인과 범위

- 사용자 지시: “너가 분석한거랑 비교해서 진행해줘”. 두 차례 조사 결과를 대조하여 MD에 반영하는 작업을 승인한 것으로 진행한다.
- 문체 기준: 사용자가 직접 쓴 “두 현장을 단순히 비교하다 보니…” 정도의 쉬운 단어와 자연스러운 흐름. 전문용어를 다른 전문용어로 바꾸거나 설명만 길게 붙이지 않는다.
- 수정 허용 파일: `01.docs/00_목차.md`, `01.docs/01_서론.md`, `01.docs/02_이론적배경.md`, `01.docs/03_시스템개발.md`, `01.docs/04_연구설계및실증분석.md`, `01.docs/05_논의및결론.md` 여섯 파일만.
- 설문 원문, 부록, 서지 목록, 작업 이력, HWPX, 분석 자료, 도구, 설정은 수정하지 않는다. 조사하지 않은 감사의 글까지 범위를 넓히지 않는다.
- 현행 작업 트리에 사용자 변경이 많다. HEAD로 복원하거나 전체 git diff를 이번 작업의 변경으로 간주하지 않는다. 착수 직전 여섯 파일의 내용을 메모리 또는 저장소 밖 임시 디렉터리에 보존해 이번 변경만 비교한다.

## Fable 대안에서 그대로 반영하지 않을 부분

- ‘도입 전후 두 번 조사했더라면 시스템 때문인지 확인할 수 있었다’는 인과 확정의 과장이다. ‘도입 전후 변화를 비교할 수 있었다’ 정도로 쓴다.
- ‘비유의’를 ‘비슷했다/같았다/뚜렷이 다르지 않았다’로 단정하지 않는다. ‘차이가 있다고 확인하지 못했다’로 쓴다. ‘유의했다’도 단순히 차이가 커 보였다는 뜻으로 바꾸지 않는다.
- 천장효과는 원문에서 가능성이므로 ‘점수가 높아 차이가 벌어지지 않았다’로 확정하지 않는다.
- 자기보고 위험 통제력 등을 실제 위험 통제 행동이 입증된 것처럼 쓰지 않는다. 관리자 평가임을 유지한다.
- ‘조정’을 모든 차이를 없앴다고 표현하지 않는다. 필요한 곳은 ‘분석에서 … 차이를 감안’으로 설명.
- 부분 η²를 전체 점수 차이 중 도입 여부의 몫이라고 단순화하지 않는다. 분모를 바꿀 수 있어 정확한 원래 정의를 유지하거나 쉬운 설명을 보완.
- 95% 신뢰구간을 개인 점수의 분포나 계산된 특정 구간에 참값이 95% 확률로 있다는 뜻으로 바꾸지 않는다.
- ‘기록을 보완할 필요’가 ‘기록하지 않았다’는 확정 사실이 되지 않게 한다.
- ‘미주입 fallback’과 제공사 장애 시 다른 모델 사용은 서로 다른 기능이므로 합치지 않는다.
- 기술적 한계/미완료 표식/숫자/인용/표·그림 번호/가설 번호/기존 표 구조를 삭제하거나 바꾸지 않는다. 신규 인용은 만들지 않는다.
- 쉽다는 이유로 ‘뭉뚱그리다’, ‘찍다’ 등 지나치게 구어적인 표현은 쓰지 않는다. 평이한 문장과 논문 문체는 함께 충족할 수 있다.
