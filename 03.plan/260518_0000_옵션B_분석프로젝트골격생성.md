폴더 구조:
D:\thesis_analysis\
├── README.md                 # 사용법

스키마 (thesis_data.db):

CREATE TABLE detections (
  id INTEGER PRIMARY KEY,
  image_path TEXT,         -- alert_snapshots/... 또는 blocked_snapshots/...
  source TEXT,             -- 'alert' or 'blocked'
  camera_name TEXT,
  timestamp TEXT,          -- 파일명 또는 history.db join으로 추출
  detection_class TEXT,    -- helmet, fall, restricted_zone 등
  yolo_confidence REAL,    -- 재추론으로 추출
  bbox TEXT                -- JSON [x1,y1,x2,y2]
);

CREATE TABLE gt_labels (
  detection_id INTEGER PRIMARY KEY,
  is_real_threat INTEGER,  -- 1: 진짜위험, 0: 가짜경보
  labeler TEXT,
  note TEXT,
  FOREIGN KEY (detection_id) REFERENCES detections(id)
);

CREATE TABLE llm_results (
  detection_id INTEGER PRIMARY KEY,
  llm_passed INTEGER,      -- 1: PASS(통과=알림), 0: BLOCK(차단)
  llm_reason TEXT,
  llm_model TEXT,
  few_shot_k INTEGER,      -- 0/1/3/5, 모르면 NULL
  prompt_profile TEXT
);

스크립트별 작업 내용:

01_reinference.py:
- D:\onvifcctv\alert_snapshots\와 blocked_snapshots\의 모든 JPEG 순회
- D:\onvifcctv\models\yolo26m.pt를 ultralytics YOLO로 로드 (conf=0.1로 광범위 검출)
- 각 이미지에서 모든 detection을 thesis_data.db detections 테이블에 INSERT
- D:\onvifcctv\data\{user_hash}\history.db에서 동일 snapshot_path를 가진 row를 찾아 
  llm_results 테이블에 second_judgment(PASS/BLOCK), llm_model, prompt_profile 채움
- 진행률 표시 (tqdm)

02_labeling_ui.py:
- PyQt6 간단한 라벨링 UI
- thesis_data.db에서 gt_labels에 없는 detection 순차 표시
- 이미지 + bbox + class + conf 보여주고 "진짜위험(Y)/가짜경보(N)/스킵(S)" 키 입력
- 진행 상황 진행률바, 저장
- 라벨러 이름은 시작 시 입력받음

03_analyze_threshold.py:
- SQL: detections × gt_labels JOIN
- conf >= [0.3, 0.4, 0.5, 0.6, 0.7] 각 임계값마다 P/R/F1 계산
- matplotlib PR Curve 그려서 output/figures/pr_curve.png 저장
- CSV 표를 output/tables/threshold_compare.csv

04_analyze_far.py:
- 1차 단독 시뮬레이션: detections에서 conf >= 0.3 모두 alert로 가정
- 2단계 시스템: llm_results.llm_passed = 1인 것만 alert
- 두 경우의 TP/FP/FN, FAR(건/시간), Precision/Recall/F1 계산
- 시간 정보는 detections.timestamp의 총 운영시간으로 정규화
- 정성 사례: BLOCK 처리됐는데 GT는 1(진짜위험)이거나, PASS인데 GT는 0(가짜경보)인 케이스 6건 골라 이미지 + reason을 markdown으로 출력

05_analyze_fewshot.py:
- 운영 중 Few-shot 설정 변경 이력이 있어야 비교 가능
- (만약 없으면) Pro 사용자 1명의 카메라에서 k=0(Few-shot OFF)/k=3/k=5 기간을 시간으로 분리해서 비교
- 또는 사용자가 직접 수동 실험 후 prompt_profile에 라벨 붙이면 그걸로 분리

config.py에 D:\onvifcctv 절대경로, models 경로, history.db 경로 등 모두 변수화.
