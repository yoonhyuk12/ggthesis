# 카피킬러 표시 문장 표현 수정

- 요청: 검사번호 00374199031 보고서에서 표시된 문장을 현재 `01.docs/` 원고와 대조하여 다시 다듬는다.
- 실행: `clean-user-facing-text` 기존 스킬 실행에 해당한다. `plan-first.md`의 기존 스킬 실행 예외를 적용하고 사용자의 명시적 문장 수정 요청 범위에서 진행한다. 보고서 지정 문장이 편집 대상이며, 별도 문체 추정기의 점수로 사용자 지정 대상을 대체하지 않는다.
- 범위: 해당 PDF의 표시 영역을 기하 정보와 텍스트로 추출하고 현행 MD 문단에 연결한다. 본문 서술의 반복·추상 표현과 문장 구조를 개선한다. 표·제목·인용·수치·수식·참고문헌·설문 문항·미확정 마커 및 연구 설계는 보존한다. 새 주장이나 근거를 만들지 않는다.
- 순서: Orca 작업자 매핑 → 파일 소유권을 나눈 문장 편집 → 작업자의 보호 항목 및 diff 검증 → 메인 검증 증거 승인.
- 원고 사실: `01.docs/` 현행 기술이 단일 기준이다. 과거 규칙의 분석 설계 요약으로 현행 원고를 되돌리지 않는다.
- 산출: 원본 MD의 해당 문단 부분 수정, 변경 이력 JSON, 범위별 검증 증거. HWPX 반영은 이번 범위에 포함하지 않는다.
- 한계: 문장 다듬기는 카피킬러 AI작성률 하락 또는 사람 작성 판정을 보장하지 않는다. 후속 카피킬러 검사 없이 새로운 작성률을 제시하지 않는다.
- 상태: 완료. 81개 표시 영역(낮음 79·중간 2)을 현행 원고에 연결하고 후보 195문단을 검토했다. 164문단에서 표시된 문장·구절을 수정하고, 고정 가설·수식 설명·주석 또는 이미 명확한 표현 31문단은 보존했다. 비서술 블록 74개도 보존했다. 실제 카피킬러 재검사 및 HWPX 반영은 수행하지 않았다.
- 매핑 증거: `.agents/watermarks-remover/local-reports/copykiller_mapping.json`. PDF 표시 본문 span 1,536개 누락 없음, 매핑 레코드 280개 문단/줄 위치 확인, 매핑 전후 MD 해시 동일. 진행 중 전달된 247은 잘못 집계된 후보 수이며 최종 범위는 195개로 확정했다.

- 검증: 각 작업자의 수치·인용·마커·수식/코드·표/제목 보존, 변경 외 바이트 보존, 역치환 원본 SHA256 복원, 줄바꿈 보존 및 문장별 의미 대조 증거를 메인이 확인했다. 동일 검사는 재실행하지 않았다. 숨은 문자 검사 결과는 0개다. 새 인용과 새 CITE_TODO는 없다.
- 장 간 파급: 주장·설계·번호·수치·용어 정의를 바꾸지 않은 표현 수정이므로 별도 내용 파급 없음.
- 제한: 자체 문체 점수는 카피킬러 AI작성률이 아니며 감소의 근거로 사용하지 않는다. 실제 판정 변화는 수정본 재검사가 필요하다.
- 별도 확인 사항: 제6장에는 결과 미확정 표시와 '비교하였다' 등 수행 완료를 뜻하는 기존 과거형이 함께 남아 있다. 수행 상태 판단은 표현만 다듬는 범위를 넘으므로 이번에는 바꾸지 않았다.

## 편집 작업자 공통 브리프

1. 소유권을 부여받은 파일만 편집한다. 매핑 JSON의 `matches`에서 해당 파일의 정확한 기존 문단을 확인하고 현재 파일과 동일한 경우에만 부분 치환한다. 원문이 달라진 경우 덮어쓰지 않고 보고한다.
2. 보고서에서 연결된 일반 서술 문단을 전부 검토한다. 문장 구조·주어·근거의 관계를 명확히 하고 불필요한 추상 표현·중복 접속을 줄인다. 단어만 기계적으로 바꾸거나 억지로 구어체로 만들지 않는다. 이미 명확하거나 보호 대상인 경우 보존 사유를 기록한다. 보고서 표시와 연결되지 않은 문단을 포괄적으로 다시 쓰지 않는다.
3. 모든 주장·사실·한계·가능성의 강도·숫자·인용은 유지한다. 결과 미수집 상태에서 결과를 만들어 쓰지 않는다. `[DATA PENDING`, `[확정 필요`, `[CITE_TODO`, `[UNVERIFIED`, `[그림 삽입 예정` 마커는 내용까지 그대로 둔다. 직접 인용·요구되는 AI 사용 공개 문구를 삭제하거나 바꾸지 않는다.
4. 표, 장·절·항 제목, 캡션, 수식, 코드, Mermaid, URL, 가설·문항의 확정 문구, 참고문헌은 그대로 보존한다. 용어 통일이나 설계 변경은 이번 범위가 아니다. 현행 MD의 통계 설계를 과거 지침 요약으로 되돌리지 않는다.
5. 박종용 교수님 논문작성요령 전문 및 관련 규칙을 읽는다. `clean-user-facing-text` 스킬을 적용하되, 편집 대상은 사용자가 지정한 보고서 표시 문단이다. 자체 문체 추정기를 카피킬러 점수나 한국어 AI 판정으로 간주하지 않는다. 단발 문장 편집만 수행하며 점수 최적화를 위한 반복 재작성은 하지 않는다. before/after 스킬 점수는 참고 기록으로만 남긴다.
6. 이전 검사에서 숨은 문자는 발견되지 않았다. 편집 후 Unicode 검사는 한 번 실시하고 보호된 문자(수학 기호·공백·인용 등)를 전체 정규화하지 않는다. 자동 정리 후보가 원문을 바꾸면 실제 문자별 의미를 확인한다.
7. 변경 이력 JSON에 각 문단의 `path`, `region_ids`, `old`, `new`, `reason`을 기록한다. 보호 항목(인용, 수치, 마커, 코드/수식, 표, 제목) 전후 보존 검사와 실제 의미 대조를 수행하고 증거를 기록한다. 바뀌지 않은 문단은 바이트 수준으로 보존한다. UTF-8 및 줄바꿈 방식을 보존한다.
8. Git 쓰기 명령, hwpx 도구(읽기 포함), 원본 PDF 변경, 다른 작업자의 파일, MEMORY·규칙·스킬·루트 문서는 수정 금지다. 계획·README는 메인만 수정한다. 새 인용은 만들지 않는다. 이미 사용된 인용 목록 및 새 CITE_TODO 없음 여부를 보고한다.
9. 완료 보고에는 검토/수정/보존 문단 수, 보호 항목 검사 결과, 남은 매핑 불확실성과 정확한 변경 이력 경로를 포함한다. 실제 카피킬러 재검사를 하지 않았으므로 예상 AI작성률이나 감소 수치를 제시하지 않는다.
