## 1. 왜 전체 조립인가

10월 4일 지도 반영으로 2장이 통째로 재편됐고(절·항 26개, 표 재번호), 1·4·5·6장도 다시 썼다. 부분 치환(`fill_hwpx.py replace`)으로 따라갈 수 있는 범위가 아니다. 또 CLAUDE.md가 2026-10-07에 "새 한글 문서는 김정년 양식 기준 원본을 복사해 시작한다"를 지정했으므로, 옛 윤혁 양식 위의 최신본을 고치는 대신 **김정년 양식 복사본 안에 MD 원고 전체를 새로 조립**한다. 기존 조립 파이프라인(`md_to_blocks.py` → `blocks_to_hwpx.py`)을 쓰되, 조립기가 옛 윤혁 양식에 고정된 부분을 양식 프로파일 주입형으로 바꿔야 한다.

**현행 조립기가 옛 양식에 고정된 지점(실측):** 전면부 `section1` 문단 수 112 검사, 표 폭 상수 39142 HWPUNIT, 표 안 첫 행을 병합해 캡션으로 쓰는 패턴(굴림 10pt), `staging/style_map.json`의 charPr/paraPr/borderFill ID 전부(옛 양식 header.xml 실측), 전면부 블록 제목 상자 패턴, 감사의 글·논문개요 보존 범위(s1 85∼111). 김정년 양식은 전면부 134문단, 표 제목이 표 밖 문단(한양신명조 11pt 가운데, 표 **위**), 자료·주 9pt, 표 머리행 회색 `#D9D9D9`·위선 0.4mm, 표 안 10pt·130%, 참고문헌 7분류 `[01]` 번호다.

## 3. 단계별 작업과 역할

HWPX 생성·COM 개방·저장·PDF 출력은 **메인(Advisor)이 단독·순차**로 한다. 워커는 읽기 전용 분석과 코드·JSON 작성만 한다(`.claude/rules/hwpx-table-layout.md`). 워커는 hwpx MCP 읽기 도구를 쓰지 않고 Python `zipfile`+`ElementTree`로만 읽는다(2.5∼3.4MB 본문).

### 2단계 — 조립기 확장 (코드, Worker Opus; 메인이 smoke 실행)

`blocks_to_hwpx.py`를 **양식 프로파일 주입형**으로 바꾼다(옛 양식 동작은 `style_map.json`으로 그대로 유지, 회귀 금지).

1. 전면부 경계·문단 수 검사를 프로파일 값으로. 표지류(section0) 텍스트 치환(제목·부제·지도교수·전공·성명·연월·심사위원란 비움).
2. **표 제목을 표 밖 문단**(11pt 가운데, 표 위, '다음 문단과 함께' 설정)으로, 표 안 캡션 행 패턴 제거. `자료:`·`주:` 문단은 9pt 왼쪽 170%.
3. 표: 머리행 회색 `#D9D9D9`·위선 0.4mm·내부 0.12mm·좌우 개방 borderFill, 셀 10pt·130%, 전체 폭은 양식 본문 가용 폭(약 140mm) 실측값, **열폭은 내용 기반 설계**(머리행·본문 글리프 폭 추정, 식별자·수치·문항·설명 열 구분; `tblplan.py`는 참고용) 합계=전체 폭, 병합 격자 보존, `repeatHeader="1"`+머리행 `header="1"`, `pageBreak="NONE"` 기본, 머리행 "라벨(단위)"는 셀 안 두 문단, `CELL` 금지.
4. 장 제목 `pageBreak="1"`, **절·항 제목 앞 빈 문단 1개**(이미 있으면 추가 금지), 제목 뒤 빈 문단 리듬은 양식대로.
5. 빨간 마커: 기존 접두사 판정(`[DATA PENDING`·`[확정 필요`·`[CITE_TODO`·`[그림 삽입 예정`·`[UNVERIFIED`, 낱말 `실험전`)과 charPr 복제 생성 로직 재사용. 참조번호·신뢰구간·양식 라벨 대괄호는 검정.
6. 그림: `figure_1-1_research_flow.png`·`figure_4-1_research_model.png`·3장 그림 4개(옛 hwpx BinData 추출)를 BinData로 삽입, 제목은 그림 **위** 11pt 가운데, 아래 `자료: 연구자 작성.`.
7. 참고문헌: 양식 서식(제목 16pt 가운데 180%, 분류 13pt 굵게, 항목 11pt 180% 자간 −2%, 내어쓰기)으로 7분류·`[01]` 번호.
8. 목차·표목차·그림목차: 양식 탭 구조(11pt 170%, 오른쪽 탭·리더)로 생성, 쪽수는 임시값 → 3단계에서 갱신.
9. 감사의 글·부록1 Part A 상자: H1·H6에 따라 옛 hwpx XML 이식(이식 블록은 charPr/paraPr/borderFill ID를 새 양식 ID로 재매핑하거나 header.xml에 추가).
10. `--smoke`로 `staging/test_out/smoke_kjn.hwpx`를 만드는 실행은 **메인**이 한다. 워커는 XML 단위 테스트(캡션 위치·borderFill·열폭 합·마커 run 분리·절 앞 빈 문단)까지만.

### 3단계 — 조립·검증 (메인 단독·순차)

1. 양식 원본 SHA256 확인 → `00. hwpx/`로 복사 → 조립 → ZIP 엔트리·XML 파싱 검증.
2. **김정년 고유 문구 0건 grep**: 원제목("건설현장 안전시설물 설치와 떨어짐 사고위험의 관계"), 성명, "안전시설물", "떨어짐 사고위험", `[작성지침]`·`[입력]`·`[미작성]`. 한 줄이라도 남으면 미완료.
3. 마커 횟수 대조: MD 기대치 vs hwpx 실제(빨간 run 소속), 반복 머리행으로 늘어난 횟수는 따로 설명. 참조번호·신뢰구간 대괄호 검정 확인.
4. 한글 COM `Open(…,'HWPX','forceopen:true')`=True → `SaveAs` 재조판 저장 → 재저장본을 산출물로. 재저장 후 charPr id가 바뀌므로 빨간 마커는 `textColor="#FF0000"` charPr를 다시 읽어 판정.
5. 재저장본을 다시 열어 PDF(스크래치) 출력 → **전 표(중첩 표 포함) 전 쪽** 확인: 하단·마지막 행·꼬리말 침범, 이어지는 쪽 머리행 반복, 표 뒤 본문 순서. 넘치는 표는 새 쪽 통째 → 열폭 재배분 → 행 경계 나눔(`TABLE`+`repeatHeader`) 순서, 필요한 표만 `treatAsChar="0"`.
6. **장·절·항이 쪽 상단에 오는지** 확인(10월 4일 지도). 제1절은 장 첫 쪽 상부. 어긋나면 빈 문단·쪽 나눔 조정 후 재조판.
7. 변경 문단의 `linesegarray` 제거 후 재조판 → 목차·표목차·그림목차의 **인쇄 쪽수**를 PDF 텍스트+이미지로 확정(물리 인덱스·고정 오프셋 금지, 반복 캡션은 첫 시작 쪽) → 목차 수정 → 다시 저장·PDF → 최종 대조.
8. 산출물 hwpx만 `00. hwpx/`에 저장. PDF·중간 파일은 스크래치.
