## 1. 문제 진단

조립기(`blocks_to_hwpx.py` + `kjn_profile.py`)는 김정년 양식 원본을 복사한 뒤 본문을 비우고 MD 블록으로 처음부터 다시 만든다. 그래서 산출물을 한글에서 고쳐도 다음 조립에서 모두 사라진다. 원본을 `--template`으로 바꾸는 것만으로는 해결되지 않는다. 본문은 어차피 다시 만들어지기 때문이다.

## 3. 해결 설계 — 조립 후 '사용자 서식 이월' 단계

새 도구는 `tools/hwpx_transfer/carry_user_format.py`이다. 입력은 기준본(사용자가 고친 최신 hwpx)과 새 조립본이고, 출력은 이월본과 보고서다.

1. **표 이식:** 두 문서의 표를 캡션(<표 N-M>)과 순서로 짝짓는다. 기준본 각 셀의 텍스트가 새 조립본의 같은 `(rowAddr, colAddr)` 셀 텍스트와 같은지 확인한다. 공백 차이는 무시한다. 병합으로 사라진 셀은 새 조립본에서 빈칸이거나 기준 셀과 같아야 한다.
   - 이 확인을 통과한 표는 **기준본의 표 XML을 통째로 이식**한다. 병합·열폭·정렬·줄간격·셀 서식이 모두 보존된다.
   - MD 수정으로 내용이 달라진 표는 이식하지 않고 새 조립본의 표를 그대로 둔다. 보고서에 '수동 재적용 필요'로 적는다.
2. **문단 서식 이월:** 표 밖 문단은 텍스트 순서로 정렬해 짝짓는다(difflib). 텍스트가 같은 문단에는 기준본의 `paraPr`(줄간격·정렬)과 `pageBreak`, 같은 텍스트 run의 `charPr`를 옮긴다.
3. **빈 문단 삭제 이월:** 기준본에서 지운 빈 문단과 짝이 되는 새 조립본의 빈 문단을 지운다.
4. **서식 ID 재매핑:** 기준본의 `charPr`·`paraPr`·`borderFill`을 실제 속성값으로 비교한다. 새 조립본 `header.xml`에 같은 정의가 있으면 그 ID를 쓰고, 없으면 새 ID로 추가한 뒤 이식한 XML의 IDRef를 바꾼다. 한글이 다시 저장하면 ID가 바뀌므로 ID끼리 비교하지 않는다.
5. 이월한 문단과 표의 `linesegarray`를 지운다. 이후 기존 3단계 절차(한글 재조판 저장 → PDF 표 검사 → 목차 쪽수 주입 → 재저장·재대조)를 그대로 따른다.
6. **보고서:** 이월 성공한 표·문단 수, 이월하지 못한 표·문단 목록(사유 포함), 기준본에만 있는 텍스트(사용자 직접 수정분 → MD 역동기화 후보)를 적는다.

조립 순서는 '조립 → **이월** → 재조판·검증'이 된다. 이월본은 다음 조립의 기준본이 되므로 사용자의 수정이 계속 누적된다. 기준본은 `00. hwpx/`의 접두사 최신본 규칙을 따른다.

### 3-1. 설계 변경(15:3x): 새 도구를 만들지 않고 `patch_from_fresh.py`를 보강한다

보강할 점:
- (a) 셀 병합 표를 자동으로 판정한다. 기준 셀 텍스트가 fresh의 같은 주소 셀과 같고, 병합으로 사라진 셀이 빈칸이거나 같은 텍스트이면 같은 표로 본다. 그러면 `--protect`를 손으로 적지 않아도 된다.
- (b) D3 바로잡기: <그림 3-1> 캡션이 앞 문단에 붙은 부분은 fresh의 두 문단으로 되돌리되, 앞 문단의 사용자 서식은 유지한다. 표 목차 '17'은 `--toc-lines`나 목차 쪽수 갱신으로 정리한다.
- (c) D2: 주제어 마커가 사라진 MD와 base가 일치하는지 확인한다.
- 검증은 fresh(현행 MD 조립본)와 base(1443)를 넣어 돌린 출력과 1443을 대조하는 방식이다. 서식·병합·열폭 차이는 0이어야 하고, 텍스트 차이는 D3 2건뿐이어야 한다.
