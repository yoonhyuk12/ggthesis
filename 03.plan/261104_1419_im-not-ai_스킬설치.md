# im-not-ai(Humanize KR v2.3.2) 프로젝트 스킬 설치 기록 (2026-11-04 14:19)

- 방식: 저장소 `install.sh --copy`가 하는 일을 전역 `~/.claude`가 아니라 **프로젝트 `.claude/`에** 그대로 재현했다(마켓플레이스·심링크 설치 아님). 저장소 클론은 세션 스크래치에만 두었고 저장소 안에 남기지 않았다.

- `.claude/skills/humanizer-kr/` — 한국어 AI 티 윤문(5개 판단 틀). 2026-10-01 자연화 2차에 사용(`261001_0554_*`).
- `.claude/skills/thesis-ai-naturalizer/` — LIS 학위논문 자연화·카피킬러 보고서 대응. 2026-10-01 자연화 1차에 사용(`261001_0432_*`).
- `.claude/skills/clean-user-facing-text/` — 유니코드 위생 + 문체 재작성. 2026-09-30 카피킬러 표시 문장 수정에 사용(`260930_2333_*`).
- 과거 계획 문서가 이 세 스킬의 경로·스크립트를 인용하지만 이력 기록이므로 고치지 않았다. 유니코드 위생은 `humanize-korean/scripts/sanitize_text.py`가 맡는다(shim이 자동 호출).
- **남긴 것:** `remove-ai-marks`는 C2PA·EXIF·XMP 메타데이터 제거와 외부 HTTP 서비스 호출이 주기능이라 윤문 스킬과 역할이 다르다고 보고 두었다. im-not-ai는 워터마크 제거 기능을 명시적으로 두지 않는다(저장소 CLAUDE.md "AI 워터마킹에 대한 입장"). 같이 지울지는 사용자 판단.

## 검증 (설치 후 실행)

- `python3 .claude/skills/humanize-korean/scripts/prepare_monolith_input.py --run-dir <스크래치>/_workspace/2026-11-04-001-smok --genre 리포트` → `00_metrics.json`·`01_input_with_metrics.txt` 생성, `route_hint=standard`, `degraded=False`. 복사 설치에서 `references/`가 `scripts/` 옆 폴백 경로로 해석됨을 확인.
- `verify_gates.py --help` 정상.
- SKILL.md의 `${SKILL_ROOT}` 유도 스니펫을 `CLAUDE_SKILL_DIR=.claude/skills/humanize-korean`과 `.claude/skills/humanize`(래퍼, 형제 폴백) 두 경우로 실행 → 둘 다 `.claude/skills/humanize-korean`으로 풀림.
- 세션 스킬 목록에 `humanize-korean`·`humanize-scan`이 자동 등록됨(래퍼 2종은 설계상 모델 호출 비노출).
- Python은 `python3` 3.12.10이 PATH에 있어 SKILL.md의 `python3` 호출이 그대로 동작한다.

## 유의

- 논문 원고에 쓸 때는 `defense-feedback`·`mark-unverified` 등 원고 규칙이 우선이며, 스킬의 4대 철칙(의미 불변·근거 기반·장르 유지·과윤문 금지)과 충돌하지 않는다. 결과물의 `[DATA PENDING`·`[CITE_TODO`·`[UNVERIFIED` 마커와 참조번호 대괄호는 스킬이 건드리면 안 되므로, 원고 문단에 돌릴 때는 브리프에 보존 목록을 명시한다.
- 업데이트는 저장소를 다시 클론해 같은 4경로를 덮어쓰는 방식이다(`update.sh`는 전역 심링크 전용).
