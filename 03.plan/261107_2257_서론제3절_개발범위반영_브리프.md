# 제3절 개발 범위·방법 보완
사용자 승인: 연구개발 설명 누락 지적 후 “반영 해줘”. 01.docs/01_서론.md 제3절에 다음을 반영한다. 교수님 작성요령 및 기존 검토 증거 승계. 사용자 직접 변경한 최신 파일을 먼저 읽어 보존한다.
1. 내용적 범위 첫 문장 “내용적 범위는 제2절의 연구 문제이다.”를 개발·성능평가·도입미도입 실효성 비교를 포함하는 범위로 바꾼다. 기존 CCTV 영상 연계, 범용 PC의 다중·단일 화면 관제, YOLO 위험 후보 탐지와 LLM 문맥 검증, 담당자 알림 연결을 설계·구현 범위로 간결히 추가한다. 제3장 실제 구현(제1절 요구사항/제3절 구현)을 읽어 명칭과 범위 대조. 외부 LLM API를 로컬 실행이라고 표현하지 말 것. 이후 기존 측정·통제변수·표본 범위는 보존한다.
2. 연구방법 첫머리에 문헌 고찰 및 현장 제약에 따른 요구사항 정리→시스템 설계·구현→현장 적용 및 운영 로그 성능평가→도입·미도입 설문 비교 순서를 명시한다. 요구사항 인터뷰/새 실험/비용절감 실증 등 하지 않은 절차를 추가하지 않는다. 실제 평가는 YOLO 위험 후보의 LLM 조건부 평가이고 횡단 지각 실효성 비교임을 유지한다. 기존 ANCOVA 설명 등 보존.
3. 문법 최소 정리: 사용자가 “시간적 범위는 … 설문으로 1회 실시하였으며”로 바꾼 문장은 “설문조사는 2026년 10월 12일부터 10월 23일까지 1회 실시하였다. 도입 현장에서는 YOLO-LLM 안전관제 시스템 설치 후 조사하였으며, 도입 전 조사는 실시하지 않았다.”로 정리 가능. 다른 정상 운용 3개월/직전1개월 내용 유지. 시간 문단에만 남은 굵은 표시는 제거. 연구방법 주어도 “본 연구는”으로 자연스럽게 맞춘다. 사용자가 삭제한 소제목형 굵은 레이블은 복원하지 않는다.
4. 제1·2절 및 다른 장 수정 금지. 상단 상태·작성 메모는 이번 변경을 기록하는 최소 수정. HWPX 반입대기 체크리스트 다음 항목 추가. 03.plan에 현재 서울시각 접두사 반영 보고서 작성 및 README에 브리프/보고서 링크. HWPX·참고문헌·그림 파일·git 쓰기 금지.
검증 1회: 최신 파일 작업전 스냅샷 대비 제1·2절 및 제3절의 요청 외 내용 보존, 제3장 근거와 추가 범위 일치, 방법에 개발 단계 포함, 가설·통계수치 불변 확인. 보고서에 실제 바뀐 문단과 검증 증거를 남기고 worker_done으로 결과 전달.
