## 2. 이동 대상 (실행)

1. `claude-skill-write-academic-report/` → `.claude/skills/write-academic-report/`
   - SKILL.md의 `name`과 디렉토리명을 일치시킨다 (Claude Code 스킬 규약).
   - git 추적 중이므로 `git mv`로 이력을 보존한다.
2. `awesome-agent-skills/` → `.claude/reference/awesome-agent-skills/`
   - 스킬이 아니라 참조 문서이므로 `skills/`가 아닌 `reference/`에 둔다. `git mv`.
3. `커맨드_및_스킬_정리.md` → `.claude/reference/커맨드_및_스킬_정리.md`. `git mv`.

   - 이미 스킬로 풀려 있으므로 원본 아카이브만 보관한다. 삭제하지 않는다.

## 4. 제자리 유지 (이유 명시)

- **`.mcp.json`** — Claude Code는 프로젝트 루트의 `.mcp.json`만 읽는다. `.claude/`로 옮기면 MCP 서버가 로드되지 않는다.
- **`skills-lock.json`** — `skills` CLI가 루트 기준으로 읽고 쓴다. 옮기면 스킬 업데이트가 깨진다.
- **`tools/hwpx_transfer/`** — 하네스 설정이 아니라 이관 작업 산출물이다. `plan/`과 QA 보고서에서 약 20곳이 이 경로를 참조한다.
- **`hwpx-mcp-simple/`** — 아래 5절 참조 (사용자 결정 대기).

## 5. 결정 필요 — `hwpx-mcp-simple/` (127MB)

`.venv/pyvenv.cfg`에 `C:\Users\EKR\orca\ggthesis\hwpx-mcp-simple\.venv`가 하드코딩돼 있고, `Scripts/*.exe` 셔뱅에도 절대 경로가 박혀 있다. 그냥 옮기면 `hwpx-mcp-server.exe`가 실행되지 않는다.

- **안 A (기본 권장): 제자리 유지.** MCP 서버 본체는 하네스 "설정"이 아니라 외부 클론 리포지토리(자체 `.git` 보유)다. `.claude/`는 설정·스킬을 두는 곳이므로 127MB 서드파티 클론을 넣지 않는다. 대신 루트 `.gitignore`에 추가해 git status를 깨끗하게 만든다.
- **안 B: `.claude/mcp/hwpx-mcp-simple/`로 이동 + venv 재생성.** 이동 후 `python -m venv .venv && .venv\Scripts\pip install .`를 다시 돌리고 `.mcp.json` 경로를 갱신한다. 재시작 후 MCP 도구가 붙는지 확인이 필요하다.
