## 산출물 (파일 2개, 경로는 과제 지시문에 있음)

### 1) `<장>.json` — 2단계가 기계적으로 적용할 삭제·치환 목록
```json
{
  "file": "01.docs/05_실증분석결과.md",
  "prose_chars_before": 27186,
  "items": [
    {"id": "05-001", "line": 13, "cat": "M", "action": "DELETE",
     "old": "<파일에서 바이트 그대로 복사한 원문. 파일 전체에서 정확히 1회만 등장해야 함>",
     "new": "", "saved": 58, "reason": "절 안내문, 목차로 대체", "keep_in": ""},
    {"id": "05-002", "line": 72, "cat": "R", "action": "REPLACE",
     "old": "<원문>", "new": "<치환문>", "saved": 140, "reason": "4장 제5절 제2항 규칙 재진술", "keep_in": "04장 제5절 제2항"}
  ],
  "structural": [
    {"id": "05-S1", "scope": "제5절 제2항 408∼416행", "proposal": "논의 5문단을 3문단으로 통합, 선행연구 대조는 각 1문장",
     "saved_est": 2500, "risk": "인용 7건 보존 필요"}
  ],
  "totals": {"items_saved": 0, "structural_saved_est": 0, "by_cat": {"M": 0, "R": 0, "H": 0, "P": 0, "T": 0, "D": 0, "L": 0}},
  "verified_unique": true
}
```
- `old`는 **파일을 Python으로 읽어 슬라이스한 원문**을 넣는다(직접 타이핑 금지 — ‘ ’ · ∼ — 같은 기호가 섞여 있다). 제출 전에 `txt.count(old) == 1`을 전 항목에 대해 확인하고 `verified_unique`에 결과를 적는다. 1회가 아니면 앞뒤 문장을 붙여 유일하게 만든다.
- 문장 단위가 기본이다. `DELETE`는 문장 통째 삭제(앞뒤 공백 처리까지 `old`에 포함: 보통 문장 뒤의 한 칸 공백을 함께 넣는다). `REPLACE`는 두세 문장을 한 문장으로 줄이거나 상호참조로 바꾸는 경우이며 `new`에 치환문을 쓴다.
- `saved` = len(old) − len(new).
- **`reason`은 "왜 이 문장이 없어도 되는지"를 통계·논문 용어를 모르는 사람도 알아듣게 쉬운 말로 쓴다(60자 이내).** 유형 코드만 적거나 "중복", "메타"처럼 한 단어로 끝내지 않는다. 사용자가 이 설명만 읽고 채택 여부를 결정한다.
  - 나쁜 예: "R(b) 재진술", "메타 서술", "과잉 유보"
  - 좋은 예: "바로 앞 문장과 같은 말을 한 번 더 함", "이 규칙은 4장 제5절에 이미 자세히 있어서 여기선 '4장 규칙을 따른다' 한마디면 됨", "표 5-6에 적힌 숫자를 본문이 그대로 다시 읊음", "'이 절에서는 ∼을 설명한다'는 안내문인데 절 제목이 이미 그 말을 함", "같은 문단에서 '단정하지 않는다'를 세 번 말해 한 번이면 충분함", "연구자가 파일을 어떻게 보관했는지는 심사에서 묻지 않는 내부 작업 메모"
- 줄바꿈은 건드리지 않는다. `old`·`new`에 줄바꿈 문자를 넣지 않는다(한 문단 안에서만 작업). 문단 전체 삭제는 `structural`로 보고한다.

### 2) `<장>.md` — 사용자가 읽을 보고서(쉬운 말, 전체 목록 포함)
사용자(논문 저자, 통계 전문가 아님)가 이 문서만 읽고 "뺄지 말지"를 정한다. 구성:
1. 맨 위에 3∼5줄 요약: 담당 장 글자 수, 후보 합계와 비율, 가장 많이 줄어드는 절.
2. 유형별 절감 표 — 유형 이름을 쉬운 말로 풀어 쓴다(예: "안내문(절 제목이 이미 말하는 내용)", "다른 장에서 이미 한 말", "표 숫자 다시 읊기", "같은 말 되풀이한 조심 문구", "연구자 내부 작업 메모", "연구 질문과 상관없는 기술 세부").
3. **전체 후보 목록 표**: `| 번호 | 행 | 원문 앞 50자… | 몇 자 줄어드나 | 왜 빼도 되나(쉬운 말) |`. 절 단위로 소제목을 나눠 넣는다. 항목이 많아도 생략하지 않는다.
4. structural(문단·항 단위) 제안: 무엇을 어떻게 줄이는지, 몇 자가 줄어드는지, 무엇이 위험한지를 각 3문장 이내로.
5. **"길지만 남겨야 한다고 판단한 문단"** 3∼5개와 그 이유(사용자가 "이건 왜 안 줄였나" 물을 곳을 미리 답한다).

## 작업 방법
1. 담당 파일 전체를 읽는다(표 행은 건너뛰어도 되지만 T 판정에는 본다). 필요하면 비교 대상 장(위 우선순위 표)을 grep으로 확인한다.
2. 문단마다 "이 문장을 지워도 심사위원이 논증 사슬(Why→How→What→의미)을 잃지 않는가"를 기준으로 고른다. 공격적으로 골라라 — 목표는 담당 장 본문 글자 수의 **25∼30%** 절감이다(과제 지시문에 목표 글자 수가 있다). 최종 채택은 사용자와 코디네이터가 결정하므로 애매하면 후보에 넣고 `reason`에 "애매"라고 적는다.
3. 큰 절감은 보통 `structural`(문단 통합, 항 축약)에서 나온다. 문장 단위로 25%가 안 나오면 structural 제안을 반드시 함께 낸다.
4. JSON을 쓴 뒤 Python으로 다시 읽어 (a) JSON 유효성, (b) 전 항목 `old`의 유일성, (c) `saved` 합계를 확인하고 그 출력(건수·합계)을 `worker_done` 요약에 넣는다.
