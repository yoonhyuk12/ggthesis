| 블록 | 대상 | 내용 |

- 치환은 정확 문자열 치환으로 하고, 각 원문이 **정확히 1건** 일치하는지 확인한 뒤 바꾼다(Python `str.count == 1` 단언). sed로 한국어를 다루지 말 것.
- 초안 문안을 심사위원의 눈으로 읽고 문제가 보이면(요령 위반, 본문과 중복, 인과·시간 표현, 사실 오류) 고쳐서 적용하되, **고친 점을 보고에 전부 명시**한다. 수치·표·표 번호·표 제목은 바꾸지 않는다.
- 제7절의 틀은 제6절(<표 4-6>~<표 4-11>)과 같게 맞춘다: why→how→what 본문 → "…는 <표 4-n>과 같다" → 표. 표 아래에는 해석 문단을 두지 않는다(요령 우선; `defense-feedback.md` 7항의 "표 아래 핵심 문장"은 11-03부터 이 틀로 대체했다).

### 2단계. 4장 표 15개 전수 점검 (고치지 않고 보고만)

<표 4-1>~<표 4-15> 각각에 대해 다음을 점검해 표로 보고한다.

| 점검 항목 | 기준 |
| --- | --- |
| why | 표 앞 문단에 "왜 이 분석(표)을 하는가"가 있는가 |
| how | 산출·판단 기준(표본, 통계량 정의, 보정, 판정 기준)이 있는가 |
| what | 결과 요지가 표 앞에 있는가(설계 표 4-1~4-5는 해당 없음) |
| 길잡이 | 표 직전 문장이 "…는 <표 4-n>과 같다"로 끝나는가 |
| 주 | 표 아래 '주:'가 남아 있는가 |

오케스트레이터의 사전 판단: <표 4-1>~<표 4-6>, <표 4-8>~<표 4-11>은 조건을 갖추었다. 다만 <표 4-6> 앞은 "왜 빈도분석을 하는가"가 약할 수 있다. 1단계에서 고친 5개 표(4-7, 4-12~4-15) 외에 보완이 필요하다고 판단한 표는 **고치지 말고** 진단과 문안 제안만 보고하고, 사용자가 이 세션에서 승인하면 반영한다(`.claude/rules/audit-before-fix.md`).

### 3단계. 검증 (증거를 보고에 붙인다)

```bash
# 저장소 루트에서
grep -n "주: " "01.docs/04_연구설계및실증분석.md"            # 0건이어야 한다
grep -n "<표 4-" "01.docs/00_목차.md"                            # 표 제목 15개가 4장 본문과 같은지 대조(변화 없어야 한다)
grep -n "제4장 제7절\|제7절 제[12]항\|<표 4-1[2-5]>" "01.docs/05_논의및결론.md" "01.docs/04_연구설계및실증분석.md"   # 상호참조가 깨지지 않았는지
git diff --stat -- "01.docs/04_연구설계및실증분석.md"
git diff -- "01.docs/04_연구설계및실증분석.md" | grep "^[-+]|"      # 표 행(| … |)이 바뀌지 않았음을 확인(출력 0줄이 정상)
```

- 표 행 diff가 0줄이 아니면 수치·표를 건드린 것이므로 되돌린다.
- 기존 `[확정 필요]`·`[CITE_TODO]`·`[UNVERIFIED]` 마커는 그대로 둔다. 새 인용을 넣지 않는다(근거가 필요하면 `[CITE_TODO: …]`).
