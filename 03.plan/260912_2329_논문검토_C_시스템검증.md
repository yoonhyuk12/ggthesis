검토일: 2026-09-12. 담당 범위: `01.docs/03_시스템개발.md` 전문, `프로그램 기술분석서.md` 전문, 연결되는 04·06장 및 로컬 실험 원자료·코드. 원고 사실의 기준은 현행 `01.docs/` MD뿐이다. `CLAUDE.md`와 `논문양식참조/박종용교수님_논문작성요령20260707.md` 전문을 읽었으며, 작성요령의 SEM 예시는 현행 ANCOVA 설계를 대체하는 요구로 해석하지 않았다.

## 1. 핵심 결론

혼동행렬 TP=39, FP=13, TN=821, FN=5와 RAG 4조건의 집계는 로컬 원자료·출력으로 재현된다. 다만 표 3-6의 Accuracy `.980`은 원분수 860/878을 한 번에 반올림하면 `.979`이며, 재현율 CI 상한 `.951`도 `.950`으로 고쳐야 한다. 1,074건의 LLM 응답 중위값은 4.1초이고, 4.2초는 신뢰도 결측을 포함한 1,095건의 값이다.

가장 큰 해석 위험은 RAG의 오경보 감소만으로 전체 우수성을 선언한 점, 후보 로그의 조건부 검증을 시스템 전체 안전성으로 넓힌 점, 전체 후보의 LLM 응답시간을 최종 경보의 종단 간 지연과 연결한 점이다. SEND 51건과 52건은 모순이 아니다. 1,074건과 878건은 서로 다른 추출 집합이며, 후자에는 신뢰도 결측 SEND 1건이 들어 있다.

판정은 **확정 오류**(산술·명시적 정의·현행 표와 서술의 불일치), **방법론 위험**(편향·해석·일반화의 위험), **미확정**(해당 실험 시점의 근거 부족)을 구분했다. 심각도 ‘높음’은 핵심 결론의 범위·재현성에 영향, ‘중간’은 방어력·재현 설명에 영향, ‘낮음’은 결론 방향을 바꾸지 않는 표기 문제를 뜻한다.

## 3. 상세 판정

### C01. 표 3-6 정확도·CI의 최종 반올림 오류

- **판정: 확정 오류 / 심각도: 낮음.**
- 근거: `01.docs/03_시스템개발.md:187`의 “0.980 … +0.930”, `:185`의 “[0.760, 0.951]”; 같은 수치의 파급 위치는 `:190`, `:226`이다.
- 독립 검산: Accuracy=(39+821)/878=**0.9794988610 → 0.979**. 1차 대비 차이는 860/878−44/878=**0.9293849658 → +0.929**. 39/44의 Wilson 95% CI는 **[0.760208475, 0.950472193] → [0.760, 0.950]**이다. 정밀도·특이도·정확도 CI의 나머지 기재 범위는 맞는다.
- F1의 원수치 차이는 0.8125−88/922=0.7170553145 → +0.717이다. 표의 +0.718은 표시값 .813−.095를 뺀 결과이므로, 변화량도 원정밀도에서 산출하는 규칙을 적용하면 +0.717로 정리한다. F1 자체 .813은 0.8125의 통상 사사오입 표기로 유지 가능하다.
- 최소 수정: 지표는 원분수로 계산한 뒤 최종 표시 단계에서 한 번 반올림하고, 표·본문·결론의 Accuracy 및 CI를 함께 맞춘다. 혼동행렬이나 성능 개선 방향이 틀렸다는 판정은 아니다.

### C02. LLM의 SEND/BLOCK을 실제 정탐/오탐으로 부른다

- **판정: 확정 오류(정의 혼용) / 심각도: 중간.**
- 근거: `01.docs/03_시스템개발.md:172` “LLM이 SEND한 정탐은 51건 … BLOCK한 오탐은 1,023건”. 같은 파일 `:154-155`는 SEND 안에 TP와 FP가, BLOCK 안에 FN과 TN이 모두 있음을 명확히 정의한다.
- 이유: 미라벨 운영 로그의 모델 판단을 사람 정답과 동일시한다. 차단율 95.25%는 실제 오탐 제거율이 아니다. 원자료에서 SEND 52건 중 13건은 실제 FP이고 BLOCK 826건 중 5건은 실제 FN이다.
- 최소 수정: “LLM의 SEND 판정 51건, BLOCK 판정 1,023건” 및 “후보 알림 차단 비율”로 바꾸고, 정탐·오탐은 사람 기준 교차표에서만 사용한다.

### C04. RAG의 “가장 효과적·구조적 회피”는 안전 성능 전체와 불일치

- **판정: 방법론 위험 / 심각도: 높음.**
- 근거: `01.docs/03_시스템개발.md:203` RAG Recall=.250, F1=.324; `:205` “가장 효과적”, “부작용을 구조적으로 회피”; `:104` “운영 중 점진적 정확도 향상을 달성”. 실제 출력 `_rag_compare_out.json:3-34`, `_agg_zeroshot_out.json:2-11`.
- 네 조건의 TP/FP/TN/FN은 제로샷 8/17/161/16, 고정3 7/11/167/17, 고정5 7/12/166/17, RAG 6/7/171/18이다. RAG는 FP를 10건 줄이는 대신 제로샷 대비 위험 검출 TP를 2건 잃고, 실제 위험 24건 중 18건을 놓친다. F1은 네 조건 중 가장 낮다. 모든 사례를 BLOCK하는 무정보 기준조차 Accuracy=178/202=.881로 RAG .876보다 높으므로, 불균형 표본에서 Accuracy 우위만으로 안전성을 판단할 수 없다. 이 비교는 무조건 BLOCK을 권하는 것이 아니라 Accuracy 해석의 한계를 보여주는 대조다.

- 최소 수정: “본 사례 표본에서 RAG는 정밀도와 FP 억제에서 유리했으나 Recall과 F1의 우위는 확인되지 않았다”로 한정한다. TP/FN을 표에 추가하고, 허용할 최소 재현율 또는 위험 누락 비용을 먼저 정한 뒤 운영점을 선택한다. 194행의 ‘소표본 사례 분석’ 인정은 유지하되 205행의 보편적 표현까지 낮춘다.

### C05. 실제 ‘고정 k’는 상한 k이며 한 건 차이를 과교정 원인으로 단정한다

- **판정: 확정 오류(조건명 불완전) + 방법론 위험(원인 귀속) / 심각도: 중간.**
- 근거: `01.docs/03_시스템개발.md:201-202` “고정 k=3”, “고정 k=5”; `:205` “11→12건 … 과교정을 유발”. `_rag_compare.py:123-130`은 `base[:5]`, `base[:3]`를 사용한다.
- 실제 등록 카드 수는 카메라별 **5,4,5,1,3,5개**다(`_rag_compare_out.json`의 각 `n_cards`; 재현 명령 아래 참조). 선곡 16건은 두 고정 조건 모두 1개, 애룡 30건은 모두 3개, 흥부 101건의 고정5는 4개다. 따라서 202개 평가 사건 각각에 정확히 5개/3개를 넣은 실험이 아니다.
- 같은 1카드 조건인 선곡에서도 다른 실행의 제로샷/고정 조건/RAG 결과가 달라질 수 있다. 각 조건을 1회 순차 호출한 자료만으로 FP 1건 차이가 예시 개수 때문인지 호출 변동·시간·설정 때문인지 분리되지 않는다.
- 최소 수정: 조건명을 “등록순 최대 3/5개(가용 수만큼)”로 바꾸고 실제 주입 수 분포를 보고한다. ‘과교정 유발’은 ‘과교정 가능성과 부합하는 관찰’로 낮추며, 반복 실행 또는 저장된 동일 사건 쌍의 변화 분석 후 확정한다.

### C06. 누수 배제는 실제 구현됐으나 시간·사건 단위 일반화는 미검증

- **판정: 방법론 위험 / 심각도: 높음.**
- 근거: `01.docs/03_시스템개발.md:194` “이미지 해시·사유 대조로 제외”. `_rag_compare.py:35-39,107-116`과 `_fewshot_run.py:99-111`은 16×16 평균해시 Hamming 거리 ≤4 **및** 정규화 사유 앞 18자 일치 조건으로 같은 사례를 제외한다. 실제 제로샷 결과에 제외 번호 301·307·70·6·404가 기록되어 있다.
- 이미 누수 방지 절차가 있으므로 ‘누수 통제 없음’이라고 판정하지 않는다. 다만 같은 사건의 근접 프레임, 같은 카메라의 유사 배경, 이미지가 같아도 사유 앞부분이 다른 경우는 현재 AND 조건만으로 배제되지 않는다. 교정 샘플 등록 시점이 평가 사건보다 앞서는지, 프롬프트·검색 규칙 선택에 평가셋 결과를 사용했는지는 출력에 없다.
- 최소 수정: 제거 기준·제외 5건·최종 202건을 구체화하고, 결과를 기존 6개 카메라의 회고적 사례 비교로 한정한다. 운영 적응 성능을 주장하려면 교정 기준시각 이전/이후 분리 또는 사건·날짜 단위 홀드아웃으로 검증한다. 현재 자료에 실제 누수가 남았다고 확정한 것은 아니다.

### C07. 단독·비눈가림 정답 판정의 편향과 위험 기준 재현성

- **판정: 방법론 위험 / 심각도: 높음.**
- 근거: `01.docs/03_시스템개발.md:146` “연구자 1인 … LLM 판정의 정·오”; `_build_merged_labeling.py:121-136` “LLM 판정을 본다”, “LLM 정탐 … 노란색”; 실제 엑셀 K열에 모델 판정, J열에 사유가 표시된다.
- 단독 라벨러라는 사실은 이미 본문에 인정되어 있다. 추가 문제는 개발자의 모델 판정·사유 노출 상태에서 ‘모델이 맞는가’를 물었다는 점이다. 신호수 존재, 정지 장비, 깊이 차이 등의 안전/위험 판단 기준이 독립된 라벨링 규약으로 충분히 제시되지 않아, 사람 정답이 모델 설명에 끌릴 수 있다. 스냅샷만으로 접근 속도·행동 전후를 판정할 한계도 있다.
- 최소 수정: 모델 출력과 독립된 실제 위험 기준을 제시하고, 전수 정답을 이미 객관적으로 확정한 것으로 표현하지 않는다. 최소한 TP/FP/FN 전건과 TN 표본을 독립 평가자가 눈가림 재판정하고 일치도·불일치 조정 절차를 보고한다. 재판정이 불가능하면 단독·비눈가림 기준의 조건부 성능이라고 명시한다.

### C08. FAR 분모와 로그 선택의 범위가 운영 오경보율 해석을 제한한다

- **판정: 미확정(196.8시간 산출) + 방법론 위험 / 심각도: 높음.**

### C09. 조건부 Recall을 전체 검출 민감도로 읽게 하는 표현과 SDT 보장 주장
