# T4 스모크 테스트 리포트 — blocks → hwpx 조립기

- 작성일: 2026-07-25
- 대상 스크립트: `tools/hwpx_transfer/blocks_to_hwpx.py`, `tools/hwpx_transfer/extract_text.py`
- 양식(읽기 전용, 무수정): `논문구조/260725_경기공학_건축안전_윤혁_논문작성.hwpx`
- **최종 조립(논문구조/ 경로 출력)은 실행하지 않았다.** 모든 산출물은 `staging/test_out/` 안에만 있다.

## 1. 실행 명령과 결과

### 1-1. 스모크 (ch01 산문 + 부록1 표 다량)

```
python tools/hwpx_transfer/blocks_to_hwpx.py \
  --template 논문구조/260725_경기공학_건축안전_윤혁_논문작성.hwpx \
  --style-map tools/hwpx_transfer/staging/style_map.json \
  --blocks tools/hwpx_transfer/staging/ch01.blocks.json tools/hwpx_transfer/staging/apx1.blocks.json \
  --references tools/hwpx_transfer/staging/references.json --smoke
```

산출물 `staging/test_out/smoke.hwpx` (77,305 bytes), 리포트 `staging/test_out/assembly_report.md`.

```
python tools/hwpx_transfer/extract_text.py --input staging/test_out/smoke.hwpx \
  --verify-blocks staging/ch01.blocks.json staging/apx1.blocks.json
→ 무결성: XML 8개 파싱 성공, 문제 0건
→ 추출 텍스트 단위: 485
→ 대조 대상 텍스트: 392, 누락: 0
```

### 1-2. 전량 드라이런 (8개 blocks 전체, 출력은 test_out)

```
--blocks ch01 ch02 ch03 ch04 ch05 ch06 apx1 apx2 --references references.json \
--output staging/test_out/full_dryrun.hwpx
→ 본문 문단 661 / 목차 항목 123(장 11) / 표 목차 35 / 그림 목차 8
→ 무결성: XML 8개 파싱 성공, 문제 0건

```

## 4. 남은 위험 — 메인이 판단해야 할 것

### 4-1. ★양식 본문의 각주 7개가 사라진다 (가장 중요)

양식 `section2`에는 사용자가 한글에서 직접 넣은 `hp:autoNum` 정식 각주 7건이 있다. 조립기는 section2를 blocks에서 통째로 새로 만들므로 이 각주는 **전부 유실된다.** 7건의 각주 텍스트가 MD 블록 어디에도 없음을 대조로 확인했다(7건 모두 미존재).

| # | 각주 텍스트(앞부분) |
|---|---|
| 1 | 건설업 업무상사고 사망자 수: 328명 (고용노동부(2024) p.18 표 기준) |
| 2 | 윤영석, 2025, 중·소규모 건설현장 안전관리자 인건비 직접공사비 계상과 안전관리 작동성에 관한 연구 |
| 3 | 이준호, 2024 건설현장 중대재해 감소를 위한 스마트 안전장비의 지원방법 개선에 관한 연구, p.30 |
| 4 | 한국산업안전보건공단, 2024, 스마트 안전장비 활용 가이드라인, p26-27 |
| 5 | Cvach, M., 2012, "Monitor alarm fatigue: An integrative review" |
| 6 | 박종학, 2024, YOLO(You Only Look Once) 모델별 건설 현장 위험 상태 및 객체 인식 성능 비교. |
| 7 | 왕인국, 2024, 건설현장 위험요인 식별을 위한 RAG와 Fine-tuning 기반 LLM 성능향상에 관한 연구 |

CLAUDE.md의 "사용자 직접 수정분 보존" 원칙에 걸리는 지점이다. 조립 전에 (a) 이 7건을 MD로 역동기화한 뒤 blocks를 다시 만들거나, (b) 조립 후 한글에서 수동 재삽입하거나, (c) 유실을 승인해야 한다. 조립기는 각주 삽입 기능을 구현하지 않았다(blocks 스키마에 각주 표현이 없다).

### 4-2. 표지 제목이 "YOLO-**VLM**" — 현행 제목은 "YOLO-**LLM**"

브리프 지시대로 치환하지 않고 위치만 기록한다. 양식 `section0`은 바이트 그대로 복사된다.

- `section0` p0(겉표지): "…중소규모 건설현장을 위한 YOLO-VLM 안전관제 시스템 실증 연구: 경보 피로도의 매개효과와 안전관리 예산 제약성의 조절효과를 중심으로…"
- `section0` p1(속표지·제출서): 같은 제목 문자열 1회
- `section0` p2(인준서): 제목 문자열 없음
- 논문개요(s1 p110–111)는 제목 상자 "논 문  개 요"와 빈 문단뿐 — 구 제목 문자열 없음

section0은 표 안 텍스트라 MCP/스크립트 치환 대상이 되며, 치환 여부는 메인이 결정한다.

### 4-3. 열폭 균등분할의 가독성 한계

브리프의 그리드 정합 원칙대로 표 폭 39142을 열 수로 균등분할하고 나머지를 마지막 열에 몰아 합계를 정확히 맞췄다(전 표 검증 통과). 다만 열이 많은 표는 열폭이 좁아진다.

| 열 수 | 열폭(HWPUNIT) | ≈ mm | 해당 표 |
|---:|---:|---:|---|
| 4 | 9785 | 34.5 | 다수 |
| 7 | 5591 | 19.7 | 9개 |
| 8 | 4892 | 17.3 | 2개 |
| 9 | 4349 | 15.3 | 3개 |

셀 최대 텍스트 길이가 104자인 표가 있어, 9열 표에서는 셀 높이가 크게 늘어난다. 내용 길이 가중 분할로 바꾸면 보기는 좋아지지만 브리프의 균등분할 지시를 벗어나므로 적용하지 않았다. **레이아웃 확인 후 필요하면 `Assembler.column_widths()`만 바꾸면 된다**(합계 보존 assert가 그대로 지켜준다).

### 4-4. 행 높이·`linesegarray`는 근사값

`cellSz.height`는 최소 1565(양식 최소 셀)에 셀 내 문단 수를 곱한 값, `tbl sz.height`는 최소높이×행수다. `linesegarray`도 charPr 높이에서 계산한 1줄짜리 근사값을 넣었다. 둘 다 한글이 문서를 열 때 재계산하는 캐시값이라 레이아웃에는 영향이 없어야 하지만, **verify-hwpx.ps1로 실제 열림·행 재배치 여부를 확인해야 최종 확정된다.** 만약 열림 자체가 실패하면 `Assembler.para()`의 `lineseg(...)` 호출을 빈 문자열로 바꿔 재시도하는 것이 첫 번째 대안이다.

### 4-5. 전면부 경계에서 1비트 수정

브리프의 "바이트 수준 그대로" 중 **표목차 제목 상자(s1 p78)만 `pageBreak="0"` → `"1"`로 바꿨다.** 양식은 표목차가 자연 흐름으로 다음 쪽에 오길 기대했으나, 목차 항목 수가 바뀌면 쪽이 어긋나기 때문이다. 그림목차 제목 상자(p82)는 이미 `pageBreak="1"`이라 무수정이다. 목차·표목차·그림목차의 **항목 문단**은 브리프 3항대로 재생성했고, 제목 상자·감사의 글·논문개요는 무수정 복사다.

### 4-6. 목차에 쪽번호·리더점이 없다

브리프 지시대로 쪽번호를 넣지 않았고, 쪽번호가 없으면 리더 파선이 허공을 채우므로 인라인 탭도 넣지 않았다. 최종본은 한글의 자동 목차 기능으로 갱신하는 것을 전제로 한다.

### 4-7. 캡션 없는 표 19개는 표 목차에 안 들어간다

blocks의 표 54개 중 19개(부록1 7, 부록2 8, 4장 4)에 `table_caption` 블록이 없다. 표 목차는 캡션에서만 파생하므로 이 19개는 목차에 나타나지 않고, 표 안 캡션 행도 생기지 않는다. MD 원고 쪽에서 캡션을 보완할지 메인이 판단해야 한다.

### 4-8. 참고문헌 표기 가정 2가지

- 항목 번호를 양식 관행(`[01] `)대로 붙였다. references.json의 `no`는 분류별 1부터다.
- `라. 관련법`은 확정 항목 0건이라 **제목만** 생성했다(빈 분류). flagged 30건은 지시대로 넣지 않았다.

### 4-9. 본문 들여쓰기는 전각 2칸이 아니라 ASCII 1칸

`template_analysis.md` 8절 5번은 "문단 첫머리에 전각공백 2칸"이라고 적었으나, 양식 section2의 본문 문단(paraPr 51 + charPr 61/62) 선두 문자를 실측하니 **U+0020 한 칸**이 지배적이었다(전각공백 U+3000 사례 없음). 조립기는 실측을 따라 본문 문단 앞에 공백 한 칸을 넣는다. 전각 2칸이 맞다면 `Document.add_blocks()`의 `prefix` 한 곳만 고치면 된다.

### 4-10. 문단 id 중복은 양식 보존분에서만 발생

생성 문단은 2147483649부터 고유 증가값을 쓴다. 출력의 중복 id(`0`×27, `2147483648`×3)는 전부 양식에서 바이트로 옮겨 온 전면부 문단이며, 양식 자체가 원래 그렇다(한글이 정상적으로 여는 관행).

## 5. 조립기가 하지 않은 일 (권한 밖 / 범위 밖)

- `논문구조/` 경로로 실행하지 않았다. 최종 조립은 메인이 한다.
- git 명령·hwpx MCP 도구를 호출하지 않았다.
- ASCII 다이어그램 3건(parse_report 5-3)의 그림 개체 재구성 — `figure_placeholder` 문단으로만 남겼다.
- 부록1 표지 박스(parse_report 5-3 후단)의 가운데 정렬 박스 재구성 — 일반 문단으로 들어간다.
- 부록 3·Abstract는 제목 + `[내용 확정 후 작성]` 자리 문단만 만들었다(`--no-tail`로 끌 수 있다).
