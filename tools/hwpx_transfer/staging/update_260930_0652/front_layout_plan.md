## 측정·추정 방법 (추정일 뿐 실제 쪽맞춤 증거가 아님)

- **surgical 모델**: `Surgical._width`를 그대로 쓴다. 글꼴은 `HYSinMyeongJo-Medium`(H2MJSM.TTF)으로 잡혔다. 다만 이 글꼴은 숫자 폭을 625로 재는데 실제 출력은 500이고, 가운뎃점 `·`은 1000으로 재는데 실제는 380이라 라틴·기호 폭을 과대 추정한다.
- **rendered 모델**: `toc2_saved.pdf` 본문 10pt 글자의 실측 진행폭을 쓴다. 한글 1000, 공백 500, 숫자 500, `·` 380이며, 측정되지 않은 기호는 Surgical 폭×0.85로 둔다.
- **줄나눔 규칙**: 셀 문단 `breakNonLatinWord=BREAK_WORD`, `breakLatinWord=KEEP_WORD`에 맞췄다. 한글은 글자 단위로 끊고, 라틴·숫자 연속 구간은 단어로 유지한다.
- **셀 높이 공식**: `inMargin 상하 282 + Σ(줄 수×크기×줄간격%) − 마지막 줄의 줄간격 여분`. 보정 결과 표 2-1·2-2·3-3·3-5의 PDF 행 높이와 ±1% 안에서 맞는다.
- **보호 단위**: 머리행 어절, 첫 열 라벨 어절(7자 이하), 라틴·숫자 토큰(식별자·연도·수치)은 한 줄에 들어가도록 열 최소폭을 잡았다. `·`과 `/` 뒤는 줄바꿈을 허용했다.
- **최적화 목적함수**: 추정 행 높이 합 + 어절 중간 분리 + 2자 이하 고아 줄 + 라틴 토큰 분리. rendered 모델 기준에 surgical 결과를 가중치 0.3으로 더했고, 여러 시작점에서 좌표 하강으로 찾았다.

## 핵심 발견: 셀 최소높이(`cellSz@height`)가 행 높이를 고정하는 표

표 3-1(idx 8), 3-8(15), 2-6(6)은 PDF 행 높이가 `cellSz` 높이 × 1.103과 정확히 같다(예: 3-1 행 3831→3826pt·100, 5591→5594). 즉 **오래된 최소높이가 내용보다 커서 행이 고정돼 있다.** 이 표들은 열폭만 바꿔서는 높이가 줄지 않는다.

3-6(13)도 2줄 행의 최소높이 2382가 남아 있어서, 폭을 바꿔 1줄이 되어도 높이가 그대로다. 이런 표는 `cellSz_reset_proposal`(본문 최솟값 1565, 3-6은 1282)을 적용해야 절감이 실현된다. 다만 사용자가 의도한 행 간격일 수 있으므로 적용 여부는 메인이 정한다.

### 쪽 복귀 가능성 (PDF pt 환산 = 감소량×1.103/100, 추정)

QA_front에서 잰 부족분(표+제목 높이 − 앞쪽 남은 공간)과 대조했다.

- **<표 2-3>**: 26쪽 부족분은 −16pt(계산상 이미 들어가지만 밀렸음)이고, 감소량은 −14.5pt다. 여유가 약 30pt가 되므로 **26쪽 복귀 가능성이 높다.**
- **<표 3-3>**: 60쪽 부족분 −1pt, 감소량 −29pt로 **60쪽 복귀 가능성이 높다.**
- **<표 3-5>**: 65쪽에 +35pt가 필요한데 감소량은 −17.6pt라 **부족하다.** 66쪽 배치를 유지한다(규칙상 허용).
- **<표 3-8>**: 70쪽 부족분 −25pt. 폭만 바꾸면 −7pt, 최소높이까지 재설정하면 −105pt로 **복귀 가능성이 높다.**
- **<표 3-1>**: 47쪽에 +17pt가 필요하다. 폭만으로는 0이고, 최소높이를 재설정하면 −86pt로 **복귀 가능성이 높다.**
- **<표 2-1>**: −17.6pt가 줄면 22쪽 남은 공간이 78pt에서 약 96pt가 된다. 23쪽으로 떨어진 `주:` 3줄(약 53pt)이 22쪽에 붙을 가능성이 있다.
- **<표 3-2>**: −46pt. 쪽 배치 문제는 없고 뒤 본문이 올라온다.
- **연쇄 영향**: 제2·3장 표 높이가 바뀌면 뒤쪽 쪽수가 이동하므로, 적용 후 **목차 쪽수를 다시 갱신해야 한다.**

## 보류와 주의

- **B3 <표 2-6> 보류.** rendered 모델에서는 최적안이 분리를 42→34로 줄이지만 surgical 모델에서는 50→52로 늘어난다. 두 모델이 상반되므로 개선이 추정 수준이다. 이 표는 어차피 TABLE 나눔이 불가피하다.
  - 높이 대부분은 최소높이 12631·14391 등에 고정돼 있다. 재설정하면 −5100(rendered)이다.
  - 표 끝의 `B-1(조기인지/)` 고아 괄호만 따로 고치려면 [6934, 7530, 7687, 8211, 8780]로 3열에 +200을 준다. rendered 기준 고아 줄 8→7, 높이 변화 0이다. 메인이 원할 때만 적용한다.
- **B10**: 줄 간격은 그대로 두는 조건이다. 최소높이를 재설정하지 않으면 높이 절감은 0이고 가독성 개선만 있다.
- **B11·B5**: 폭 변경은 가독성 개선이다. 쪽 복귀의 결정 요인은 최소높이 재설정이다.
- 제안값 적용 뒤에는 폭을 바꾼 표의 셀 문단과 앵커 문단에서 `linesegarray`를 제거하고, 한글에서 재조판 저장한 PDF로 **바뀐 쪽만** 다시 확인한다. 후속 확인 요청이 오면 해당 쪽만 재검한다.
- 이번 작업 범위 밖: 그림 목차의 `<그림 1-1>` 누락(메인 직접 처리), MD 원고, HWPX 쓰기.

## 추가: 행별 최소높이 제안 (코디네이터 규칙)

JSON의 `row_min_height_proposal`은 `min(현재 cellSz 높이, 새 폭의 rendered 추정 행 높이)`로 계산했다. 한 행의 모든 셀에 같은 값을 넣으면, 실제 내용이 더 필요한 곳은 한글이 자동으로 늘린다.

B7·B8·B2·B9·B1은 현재값과 같거나 더 낮을 필요가 없다. 실질적으로 줄어드는 표는 B5(3-1)·B11(3-8)·B10(3-6)이고, B3(2-6)은 보류 상태다. 추정이 불확실한 B3은 **현상유지**로 둔다.
