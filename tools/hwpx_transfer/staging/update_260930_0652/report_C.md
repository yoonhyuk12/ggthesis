# report_C — 표 내부 변경 명세 (C 담당)

- 입력: `base_paras.json`·`base_tables.json`(최신 HWPX `260913_0320` 덤프), `old_blocks.json`(f5588d2 MD), `new_blocks.json`(현행 MD). 3자 대조.
- 산출: `tables_C.json` (스키마 `cell_replace`·`replace_table`·`insert_table`·`delete_table`·`user_edits`·`coverage`·`validation`). 재생성 명령: `PYTHONDONTWRITEBYTECODE=1 PYTHONIOENCODING=utf-8 python C_build.py --probe`
- 코드: `C_common.py`(로더), `C_analyze.py`(3자 대조 진단), `C_build.py`(명세·검증).
- HWPX 쓰기·COM·MCP는 사용하지 않았다. `--probe`는 `base.hwpx`를 메모리로만 열어 기존 `Surgical.table_fragment`가 재구성·삽입 명세 8건을 모두 받아들이는지 확인한다(파일 쓰기 없음). `base.hwpx`의 SHA256은 `source.json`과 같다(`7e14f621…85a4`).

2장 표의 앵커와 순번은 코디네이터가 최종 확정한 값이다(메시지 "최종앵커 결정 — A 제안으로 통일"). 처음 제안한 320/367 제자리 교환안은 철회했다. 모든 표 제목은 base 관례대로 **병합 첫 행**에 넣으며, A는 별도의 캡션 문단을 만들지 않는다. 이 사항은 A·B에 전달했다.

### cell_replace의 MD 변경 40건

- 2장: <표 2-3> 1셀(이준호 2024 핵심 결과).
- 4장: <표 4-1> 1셀·<표 4-2> 1셀(H1 문구), <표 4-3> 출처 1셀, 설문표 B(9셀)·C(4)·D(9)·E(4)는 참조번호를 저자·연도로 바꾸고 문항을 수정했다. 수정 문항은 B-3, D-6, D-7이다.
- 5장: <표 5-9> H1 문구 1셀.
- 부록: 두 양식 표지 안내문 4문단(2235·2236·2507·2508), 설문 격자의 문항 셀 4개(B-3: t43·t50, D-6·D-7: t45). 리커트 응답 격자·병합·중첩 Part A 표(t41·t48)는 건드리지 않는다.

`실험전` 564칸은 코디네이터 Q1 회신을 따랐다. MD가 명시한 결과칸 가운데 **base가 빈칸인 칸만** 채웠다. 숫자나 사용자 입력이 있는 칸은 대상이 아니며, 실제로 해당 칸이 없었다. 빨간색은 메인 조립 단계에서 입힌다.

### user_edits (보존, 치환 대상 아님)

- t9(<표 3-4>) 4셀: base는 `TP` / `진양성(…)` 두 문단으로 나뉘어 있다. MD는 `TP — 진양성(…)`로 old와 new가 같으므로 base를 유지한다.
- t24(<표 5-1>) `발주청` 축약, `현장 공사금액 규모`의 마커 삭제, 합계 행 비율 `100.0` 3칸의 빈칸 처리: 모두 사용자 직접 수정으로 판단해 보존한다.
- 충돌(old ≠ base이면서 new도 다른 경우)은 0건이다.

## 1회 검증 결과 (`tables_C.json['validation']`)

- `cell_replace` old 일치 604/604. `(section, idx)` 중복이 없고, 모두 표 셀 문단이며, 재구성·삭제 표와 겹치지 않는다.

- 표 목차(section1)는 표 바깥 문단이라 C 범위가 아니다. <표 1-1> 신설, <표 2-5>~<표 2-7> 번호 변경을 목차에 반영해야 한다.
