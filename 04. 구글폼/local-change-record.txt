- sync_source.py: 이번 전자 설문 분기 결정을 원고의 지정된 문구에 한 번 적용한 이력용 스크립트. 이미 적용했으므로 다시 실행하지 않는다.

전자 설문 구조
START 첫 질문은 도입현장 / 미도입현장 필수 단일 선택이며 배포코드·성명 필수 입력이 뒤따른다.
도입현장: A(9) → B(8) → C(4) → D(8) → E(4) → 제출.
미도입현장: A(9) → B(8) → C(4) → 제출.
측정 문항은 도입 33개, 미도입 21개. 관리 항목 3개 포함 실제 경로 질문 수는 36개, 24개이다.
편집기에는 경로별 A/B/C 복제본 때문에 총 57개 질문과 9개 섹션이 생긴다.
분기 선택은 점수나 공변량으로 쓰지 않는다. 분석용 집단은 연구자가 확인한 명부를 따른다.
응답 내보내기 후 경로별 A/B/C 두 열 묶음을 같은 문항 ID로 합친다.

2026-10-12 후속 변경 — 현장명 입력
사용자 지적에 따라 현재 설문 관리 항목은 현장 구분·현장명·성명이다. 현장명·성명으로 명부를 대조한 연구자가 내부 현장 ID를 부여하며, 분석용 사본에서는 현장명과 성명을 모두 제거한다.
survey-spec.json, browser-build-instructions.txt, build_spec.py, validate_spec.py는 현재 현장명 기준이다. site-name-update.txt에 외부 폼의 정확한 변경 전후 문구, site-name-validation.json에 측정 문항 불변 증거를 저장했다.
complete-survey.gs, browser-spec-comparison.json, 기존 확인화면은 이전 배포코드 버전의 실행·검증 이력으로 보존한다. complete-survey-site-name.gs는 현장명으로 동기화한 로컬 사본이며 실행하지 않았다. sync_source.py도 이전 분기 변경 당시의 일회성 이력이다.
외부 폼의 현장명 적용 여부와 브라우저 재확인은 메인 작업자가 기록한다.
