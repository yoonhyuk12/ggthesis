# HWPX 표 생성·배치 규칙

이 규칙은 `paths:` 제한 없이 항상 로드한다. 루트 `00. hwpx/`·`tools/hwpx_transfer/`, 중첩 논문 `04. 미소논문/00. hwpx/`·`04. 미소논문/tools/hwpx_transfer/`와 향후 다른 논문 경로의 **새 HWPX 생성·MD 이관·전체 조립·기존 표 부분 수정 모두**에 적용한다. 경로는 저장소 상대경로로 기록한다. 기존 파일의 부분 수정 절차는 [부분 수정 스킬](../skills/hwpx-thesis-editing/SKILL.md), 공통 개방·저장 검증은 [산출물 검증 규칙](hwpx-output-verification.md)을 함께 따른다.

## 원본과 내용 보존

- HWPX 생성·수정·한글 COM 조작과 저장은 **메인 컨텍스트가 단독·순차로** 수행한다. 워커는 읽기 전용 분석과 허용된 규칙·코드 작업만 한다. 기존 원본은 SHA256을 기록해 불변을 확인하고, 항상 복사본에서 작업해 새 이름으로 저장한다.
- 내용이 바뀌면 해당 논문의 MD 원고를 먼저 수정한 뒤 HWPX에 반영한다. **열폭·줄간격·여백·쪽 나눔·점선 목차의 조판 쪽수만 바꾸는 작업은 MD를 수정하지 않는다.** 기존 HWPX의 사용자 직접 수정분은 보존하고, 무단 전체 재생성으로 없애지 않는다.
- 표·셀·문단·run의 텍스트와 순서, 글꼴·크기·장평·자간·강조·색, 각주·참조번호·설문 선택기호를 보존한다. `[DATA PENDING`·`[확정 필요`·`[CITE_TODO`·`[그림 삽입 예정`·`[UNVERIFIED`는 닫는 대괄호까지 빨강을 유지한다. 참조번호·신뢰구간·설문 양식 라벨의 대괄호는 검정이다. 공간 확보를 위해 문구나 마커를 삭제·축약하거나 글자 크기를 임의로 줄이지 않는다.

## 생성 전에 내용으로 열폭을 설계한다

1. 제목·머리행과 모든 본문 셀을 읽고 식별자, 수치, 문항, 설명, 근거 열을 구분한다. **균등 열폭을 기본값으로 생성하지 않는다.** 폭 요구가 비슷한 수치 비교 열·Likert 응답 격자만 균등 폭을 허용하며, 같은 표의 긴 문항 열까지 균등하게 만들지 않는다.
2. 실제 적용 글꼴의 한글·영문·숫자·기호 **글리프 폭**, 글자 크기·장평·자간과 문단 들여쓰기·줄간격·문단 앞뒤 간격, 셀 좌우·상하 안쪽 여백을 반영해 줄바꿈과 높이를 추정한다. 글자 수만으로 폭을 정하지 않는다. 실제 글꼴 측정이나 한글 출력 PDF의 글리프 측정을 쓰되 대체 글꼴·혼합 글꼴 통계는 추정임을 기록하고 재조판으로 확인한다.
3. 짧은 번호·구분 열은 필요한 만큼만 배정하고 긴 설명·근거·문항 열에 폭을 준다. 머리행 라벨과 단위 괄호는 두 문단으로 분리하는 기존 규칙을 지킨다. 허용된 양식 안에서 여백·줄간격을 조정할 수 있지만 가독성과 실제 글꼴은 유지한다.
4. 기존 표는 **전체 폭 `hp:sz@width`를 보존**한다. 새 표는 해당 구역의 본문 가용 폭 안에서 전체 폭을 먼저 확정한다. 정수 HWPUNIT 열폭 배열의 합이 전체 폭과 정확히 같아야 하며, 반올림 잔차까지 배분한다. 셀 폭은 `sum(열폭[colAddr:colAddr+colSpan])`으로 산출한다.
5. `rowCnt`·`colCnt`, `cellAddr`의 `rowAddr`·`colAddr`, `colSpan`·`rowSpan`을 보존하고 병합 셀까지 확장한 점유 격자로 중복·빈칸·범위 초과가 없는지 확인한다. 위 행에서 이어지는 `rowSpan`도 점유하므로 각 행에 새로 시작하는 셀만 합산해 정합 판정을 하지 않는다.
6. **중첩 표·설문 양식은 별도 설계한다.** 바깥 표의 안내문·양식 틀과 안쪽 응답 격자를 각각 식별하고, 안쪽 표 폭은 부모 셀의 좌우 여백을 뺀 가용 폭 안에 둔다. 바깥·안쪽 표를 하나의 열 배열로 평탄화하거나 일반 표용 일괄 패치를 적용하지 않는다. 문항·척도·체크박스와 병합 구조를 보존하고 각 수준을 따로 검증한다.

## 쪽맞춤과 나눔 순서

본문 가용 높이는 해당 구역의 `pagePr@height - margin(top + bottom + header + footer)`로 계산한다. 현재 쪽에서는 앞선 본문·표 제목·문단 간격·앵커가 차지한 공간도 빼고, 실제 꼬리말 위치와 충돌하는지 출력으로 확인한다. `<hp:cellSz height>`는 **최소 높이**이며 합계가 가용 높이보다 작아도 내용이 들어간다는 증거가 아니다. `linesegarray`와 표 높이 캐시도 변경 전 조판 값일 수 있다.

`tools/hwpx_transfer/tblplan.py`와 중첩 논문의 같은 도구는 최소 높이에 기반한 **참고용 경고·계획**이다. `fits`·`OK`를 완료 판정으로 사용하지 않는다. 행 높이 축소 권고도 실제 내용을 잘라 넣으라는 뜻으로 적용하지 않는다.

1. **새 쪽에서 실제로 한 장에 들어갈 표라면** `pageBreak="NONE"`으로 통째 배치한다. 속성만으로 이동했다고 가정하지 말고 제목과 표의 실제 시작 위치를 확인한다. 새 쪽에서도 넘치는 표를 계속 통째로 밀지 않는다.
2. 여전히 넘치면 위 내용·서식 기준으로 **열폭을 재배분**하고 재조판한다. 전체 폭과 병합 격자를 보존한다.
3. 그래도 넘치면 **행 경계 나눔** `pageBreak="TABLE"`과 `repeatHeader="1"`을 사용한다. 실제 머리행의 셀 `hp:tc@header="1"`을 지정하고 일반 본문 셀에는 잘못된 머리행 플래그가 남지 않게 한다. 병합된 제목행·다단 머리행은 연속된 머리 영역으로 확인하여 반복 여부를 결정한다. 단일 행이나 병합 영역 자체가 한 쪽보다 높으면 완료 처리하지 말고 구조 해결 필요를 보고한다.
4. `hp:pos@treatAsChar="1"`(글자처럼 취급)은 나눔을 막을 수 있다. TABLE 설정 후에도 실제로 나뉘지 않는 **필요한 표만 `0`으로 전환**한다. 모든 표에 일괄 적용하지 않는다. 변경 뒤 앵커 문단, 배치 기준·오프셋·본문 감싸기, 앞뒤 본문 순서, 특히 뒤따르는 본문의 중첩·가림·유실을 확인한다.

**`pageBreak="CELL"`은 절대 사용하지 않는다.** 글자 크기나 최소 행 높이를 억지로 줄여 맞추지 않는다. 텍스트뿐 아니라 열폭·글꼴·줄간격·여백·배치가 바뀐 셀 문단 및 영향을 받는 표 앵커 문단의 `<hp:linesegarray>`를 제거하고 한글이 다시 계산하게 한다. 무관한 문단의 캐시는 건드리지 않는다.

## 실제 산출물 완료 조건

메인이 한글 COM `Open` 성공을 확인하고 **한글에서 재조판 `SaveAs`한 HWPX**를 다시 열어 PDF를 내보낸다. ZIP/XML 통과나 COM 개방 성공만으로 완료라고 하지 않는다. 재저장 시 스타일 ID가 바뀔 수 있으므로 ID 자체가 아니라 실제 참조 글꼴·서식·색과 텍스트를 비교한다.

- **모든 표**(중첩 표 포함)의 모든 쪽을 PDF에서 확인한다. 표 하단·마지막 행·각 셀 끝 문장이 꼬리말/쪽번호 영역을 침범하거나 잘리지 않아야 한다. 이어지는 쪽의 행 연속성·머리행 반복, 표 뒤 본문의 위치·순서를 확인한다. PDF 텍스트 추출과 페이지 이미지 육안 확인을 함께 사용한다.
- 반복 문구는 문서 어딘가에 한 번 발견됐다는 이유로 통과시키지 않는다. 셀·행·표별 마커의 **기대 출현 횟수와 실제 횟수**를 대조하고, 반복 머리행으로 늘어난 출력 횟수는 따로 설명한다. 마커 끝부분과 빨간색도 검사한다. 자동 매칭이 애매하면 해당 쪽을 직접 확인한다.
- 재조판 후 **점선 목차·표 목차·그림 목차의 인쇄 쪽수**를 갱신한다. PDF 파일의 물리 페이지 인덱스를 인쇄 쪽수로 쓰거나 고정 오프셋을 가정하지 않는다. 반복 캡션이 여러 쪽에 나타나면 제목·표 식별자·본문 시작을 함께 대조해 **확인된 첫 시작 쪽**으로 매핑한다. 목차 수정 뒤 다시 저장·PDF 출력하여 목차 변경에 따른 쪽 이동까지 최종 대조한다.
- 원본 SHA256 불변, 텍스트·서식·마커 보존, 전체 폭·병합 격자 정합, 전 표 검증 결과, 목차의 실제 인쇄 쪽수 대응을 증거로 남긴다. 자동 도구의 누락·꼬리말 경고는 검토 단서이며 재조판 후 실제 출력으로 해소해야 한다.

## 근거와 도구의 한계

2026-09-12 [표 감사 자료](../../04.%20미소논문/tools/hwpx_transfer/staging/table_fit_260912/table_audit.json)는 `before_hancom_resave`, `ok: false`이며 표 인덱스 7·13·21·38·43에 꼬리말 침범 검토를 요구한다. 이 최상위 결과는 수정 전 진단이며, 같은 JSON의 `split_candidate_verification.ok: true`는 분할 후보의 최종 45표 검증 성공을 나타낸다. 두 단계를 구분하고 수정 전 실패를 최종 실패로 인용하지 않는다. 최소 높이·균등 폭만으로 판단하지 않고 실제 재조판 결과를 검증해야 한다는 사례다. 같은 폴더의 [열폭 조정 스크립트](../../04.%20미소논문/tools/hwpx_transfer/staging/table_fit_260912/apply_table_widths.py)와 [표 검증 스크립트](../../04.%20미소논문/tools/hwpx_transfer/staging/table_fit_260912/verify_tables.py)는 측정·검증 참고 자료이며, 세션 전용 인덱스·구역·PDF 매칭 가정을 새 문서에 그대로 적용하지 않는다. 이 규칙을 위해 훅이나 설정을 추가하지 않는다.
