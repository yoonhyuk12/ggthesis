# Ⅲ. 제안 시스템

## 3.1. 설계 목표와 이중 캐스케이드 아키텍처

중소규모 건설현장은 전담 안전관리자의 부재(김석기, 2026), 안전관리비 준수율 36.7%에 그치는 예산 제약(조도빈, 2026), 라벨 데이터 부족(Kim, 2025)이라는 구조적 제약을 가지며 기존 ONVIF 카메라 인프라의 재활용은 비용 제약을 해소하기 위한 핵심 전제이다. 본 연구는 이러한 제약을 충족하기 위해 다섯 가지 설계 요구사항을 도출하였다. 일반 사무용 PC에서 구동 가능할 것(R1), 기존 ONVIF IP 카메라와 호환되는 RTSP 스트림을 처리할 것(R2), 현장별 재학습 없이 현장 적응이 가능할 것(R3), 오탐률이 경보 피로를 유발하지 않는 임계치 이하로 유지될 것(R4), 영상 프레임 단위의 실시간 처리가 가능할 것(R5)이다. 본 연구에서 '실시간성(R5)'은 순간적 처리가 아니라 위험에 대응 가능한 시간 창(reaction window) 안에서의 경보 도달, 즉 적시(right-time)로 정의한다(Teizer, 2016). 검출-알림 지연을 10초 미만으로 단축할 때 실시간 예방·시정 효과가 극대화됨을 보고한 대규모 실배치 연구(Zhang et al., 2026)에 근거하여, 본 연구는 검출부터 사용자 단말 알림 도달까지의 종단간 지연 10초 미만을 실시간성(R5)의 정량 기준으로 설정한다.

본 시스템은 신호감지이론(Signal Detection Theory, SDT; Green & Swets, 1966)에 근거하여 1차는 민감도(sensitivity) 극대화, 2차는 특이도(specificity) 극대화로 역할을 분담하는 캐스케이드 구조를 채택한다. SDT는 신호와 잡음이 중첩된 환경에서 결정 임계값(criterion)의 위치에 따라 적중(hit)과 오경보(false alarm)가 상쇄(trade-off) 관계를 이룬다고 본다. 단일 검출기로는 이 상쇄(trade-off)를 회피할 수 없으나, 서로 다른 기준값(criterion)을 가진 두 단계를 직렬 연결하면 1차의 높은 적중률(hit rate)과 2차의 낮은 오경보율(false alarm rate)을 동시에 확보할 수 있다. Cvach(2012)가 의료 알람 분야에서 권고한 지능형 알람(Smart alarms) 역시 동일한 원리에 기반한다. 본 시스템의 전체 처리 흐름은 ONVIF 카메라의 RTSP 스트림이 YOLO 1차 고민감도 검출 모듈로 입력되고, 검출 결과가 LLM 2차 퓨샷(Few-shot) 검증 모듈을 거쳐 알림 앱으로 전파되는 4단계 파이프라인으로 구성된다(그림 2).

```
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│  Stage 1         │   │  Stage 2         │   │  Stage 3         │   │  Stage 4         │
│  Stream Ingest   │──▶│  YOLO Detection  │──▶│  LLM Verification│──▶│  Alert Routing   │
│  (ONVIF / RTSP)  │   │  (Conf 0.3)      │   │  (Few-shot)      │   │  (알림 앱)       │
└──────────────────┘   └──────────────────┘   └──────────────────┘   └──────────────────┘
       영상 수신             민감도 ↑              특이도 ↑             다중 수신자 전파
       (ONVIF/RTSP)         (YOLO 객체탐지)     (멀티모달 LLM)         (현장대리인·안전관리자·감리원)
```

본 시스템은 일반 사무용 PC에서 동작하는 데스크톱 응용으로 구현되며, ONVIF 표준 카메라의 RTSP 스트림을 입력으로 받아 YOLO 객체 탐지와 멀티모달 LLM 검증을 수행한다. AI 추론은 가용 GPU 자원에 따라 가속 경로를 자동 선택하며, LLM은 상용 멀티모달 모델 다수에 대해 다중 프로바이더 폴백 구조를 적용해 가용성을 확보한다. 확정된 경보는 알림 앱으로 다중 수신자에게 동시 전파된다.

## 3.2. 1차 검출: 고민감도 YOLO 객체 탐지 모듈

기존 YOLO 기반 건설안전 연구는 오탐 우려로 신뢰도 임계값(confidence threshold)을 통상 0.4~0.5 수준에서 운용해 왔으며(박종학, 2025) 이로 인해 미탐(false negative)이 증가하는 한계를 보였다. 박종학(2025)은 통상 임계값에서 Forklift·Scaffold 등 일부 위험 클래스의 재현율(recall)이 낮아지는 한계를 보고하였다. 본 시스템은 SDT의 민감도–특이도(sensitivity–specificity) 분리 원칙에 따라 1차 단계에서는 재현율(recall) 극대화를 목표로 임계값을 0.3으로 하향한다. 이로 인해 발생하는 오탐은 2차 LLM 단계가 문맥 검증으로 필터링한다. Kim et al.(2025)은 임계값을 0.3으로 하향(τ_mod=0.3)하는 같은 방향의 전략으로 화재 검출 재현율(recall)을 0.904까지 끌어올리고 F1을 0.863에서 0.8895로 향상시킨 바 있어 본 연구 설계의 직접적 근거가 된다. 본 시스템은 YOLO26 계열의 중형(medium) 변형(YOLO26m, COCO val 기준 mAP50 0.651; Ultralytics, 2025)을 기반으로 작업자, 안전모·안전조끼 착용 여부, 중장비, 사다리, 비계, 낙상, 자유 객체 등을 검출하며 사전학습 가중치를 그대로 사용하고 추가 미세조정(fine-tuning)은 수행하지 않는다.

## 3.3. 2차 검증: LLM 기반 백업 검증 모듈

본 절은 본 연구의 핵심 기여를 다룬다. 본 모듈은 멀티모달 LLM이 1차 YOLO의 알람 메타데이터(카메라명·warning_key·warning_message)와 원본 프레임 이미지, 카메라별 사용자 교정 샘플을 입력받아 영상·텍스트 통합 추론으로 정탐·오탐을 재판정하는 것을 골자로 한다. YOLO가 구조적으로 다룰 수 없는 객체 간 관계·상황 문맥·상식적 추론을 LLM이 보완함으로써 단일 모델로는 불가능한 특이도(specificity) 회복을 달성한다. 본 모듈의 두 가지 핵심 메커니즘은 LLM의 ① 멀티모달 문맥 추론에 의한 오탐 기각(3.3.1), ② 맥락 내 학습(In-context Learning) 특성을 활용한 퓨샷 기반 현장 적응(3.3.2)이며, 이를 통해 미세조정(fine-tuning) 없이도 현장별 적응이 가능하다.

### 3.3.1. 검증 필요성과 입출력 구조

1차 YOLO 검출은 자연 배경 오인식(나뭇가지를 사다리로), 작업복 패턴 오인식(줄무늬를 안전조끼로), 정상 자세 오인식(쪼그려 앉기를 낙상으로), 문맥 무관 오인식 등 네 가지 유형의 구조적 오탐을 발생시키며, 이러한 오탐은 임계값 상향만으로는 미탐 증가 없이 해결할 수 없다. 본 시스템은 이를 해결하기 위해 멀티모달 LLM을 2차 검증기로 도입한다. LLM은 1차 YOLO 검출 결과의 알람 메타데이터(카메라명·warning_key·warning_message)와 원본 프레임 이미지, 카메라별 사용자 교정 샘플(별도 user 메시지로 자동 주입)을 입력으로 받아 검출 영역을 자연어로 지목·해석하고, 정탐·오탐 판정(`result`: SEND/BLOCK)과 한국어 자연어 사유(`reason`: ≤80자) 두 필드만으로 구성된 JSON 스키마를 출력한다. `reason` 필드는 그대로 알림 앱 메시지로 활용되어 별도 요약 단계가 불필요하다. LLM이 2차 검증기로 적합한 이유는 ① 영상-언어 결합 추론으로 객체의 시각적 특성과 주변 맥락(예: 작업복 패턴 vs 반사 소재, 비계 위 자세 vs 자재 운반 자세)을 통합 판단할 수 있고, ② 사전 정의된 규칙 없이도 산업안전 분야의 상식적 지식을 활용할 수 있으며, ③ 판정 사유가 한국어 자연어로 출력되어 사용자가 결과를 검증·교정할 수 있고 알림 앱 메시지로 그대로 활용 가능하다는 세 가지 특성을 동시에 충족하기 때문이다.

### 3.3.2. Few-shot Learning 기반 현장 적응

본 시스템은 미세조정(fine-tuning) 없이 건설 현장용 시스템 프롬프트와 카메라별 사용자 교정 샘플을 결합하여 현장 적응을 달성한다. 이 접근은 라벨 데이터 구축 비용을 제거하고, 현장 규칙 변경 시 프롬프트 수정만으로 대응 가능하며, 사용자가 직접 오판 사례를 교정할 수 있다는 세 가지 이점을 가진다. 시스템 프롬프트는 건설안전 검토자 페르소나("You are a construction site safety officer")로 시작하여 출력 스키마(Output)·우선 규칙(Priority Rule)·SEND 조건·BLOCK 조건·핵심 원리(Key Principle)의 다섯 섹션으로 구성된다. LLM이 동일한 오판을 반복하는 경우 사용자는 알림 이력에서 우클릭으로 교정 샘플을 등록하며, 사유(10~80자)·교정 이미지와 함께 카메라별로 저장된다.

다만 누적된 교정을 매 호출에 무차별 주입하는 방식은, 관련 없는 교정이 끼어들어 새로운 오판을 유발하거나 동일 방향의 교정이 과다하게 쌓여 판정이 한쪽으로 쏠리는 부작용을 일으킨다(4.3절에서 실증). 본 시스템은 이를 방지하기 위해 **현재 알림과 같은 맥락의 교정만 선택적으로 검색하여 주입하는 RAG(Retrieval-Augmented Generation) 방식**을 채택한다. 구체적으로 교정 등록 시 현재 알림과 같은 맥락으로 분류하여 저장하고, 알림 발생 시 같은 맥락의 교정만 최대 3건까지 검색하여 본 검증 LLM의 프롬프트에 원본 프레임과 함께 주입한다. 같은 맥락의 교정이 없으면 주입하지 않는다(미주입 fallback). 이는 In-context Learning(Brown et al., 2020)을 검색 기반 예시 선택과 결합한 것으로, 관련성 높은 최소한의 교정만으로 운영 중 점진적 정확도 향상을 달성한다.

### 3.3.3. 통합 판정과 3단계 오탐 억제

본 시스템은 YOLO 1차 결과와 LLM 2차 결과를 결합하여 3단계 파이프라인으로 알림 여부를 결정한다. 1단계 1차 확인 필터는 단발성 오탐을 거르기 위해 일정 시간 창 내 재감지 또는 연속 프레임 감지를 요구한다. 2단계 LLM 문맥 검증에서는 `result=SEND`로 판정된 사건만 알림 단계로 진행되고 `BLOCK`으로 기각된 사건은 저장되어 추후 분석·교정에 활용된다. 3단계 쿨다운 필터는 동일 사건의 중복 알림을 억제한다. LLM API 장애 시에는 안전 폴백으로 1차 결과만 발송하되 "LLM 검증 실패" 태그를 부착하여 사용자가 결과의 신뢰 수준을 식별할 수 있도록 하며, LLM이 정탐을 오탐으로 잘못 기각한 사례는 사용자가 퓨샷(Few-shot) 교정 샘플로 등록 가능하다.

## 3.4. 실시간 경보 전파

확정된 경보는 알림 앱을 통해 동시 전파된다. 메시지는 LLM이 출력한 한국어 자연어 사유(`reason` 필드)와 검출 프레임 이미지를 포함하며 다중 수신자에게 자동 분류 라우팅된다. 본 시스템의 위험알림 수신자 범위는 관련 법령에 근거하여 ① 「건설산업기본법」에 따른 현장대리인(현장배치 건설기술인), ② 「산업안전보건법」에 따른 안전보건관리책임자 및 안전관리자, ③ 「건설기술 진흥법」에 따른 발주청 소속 공사감독자 또는 지정 건설사업관리기술인(감리원)으로 정의한다. 알림 앱에 표시되는 위험 알림 예시는 그림 5와 같다.
